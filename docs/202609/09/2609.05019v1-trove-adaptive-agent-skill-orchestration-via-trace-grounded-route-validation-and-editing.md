## 摘要
智能体往往在观察到决定性的运行时结果之前，就倾向于优化、选择或限制执行结构。然而，这种执行前承诺造成了编排瓶颈：当中间证据使待定的后续步骤失效时，智能体必须要么执行过时的步骤，要么进行广泛的重新规划，这会导致错误累积、计算浪费，并丢弃已有进展。因此，我们提出基于轨迹验证与编辑的路径编排方法（TROVE），它只修改运行时证据所失效的部分。离线阶段，TROVE 将评估过的工作流搜索轨迹提炼为原子技能和复合技能，以及一个受结果影响的条件转移图，在保留稳定片段的同时暴露依赖结果的决策。在线阶段，它将规划路径视为暂时的：在提交一个顶级技能后，控制器保留有效的续接路径，插入由轨迹支持的局部响应，或仅替换失效的后缀部分。在代码生成、问答和数学推理基准测试中，使用不同的 LLM 后端的评估表明，与现有的数据集级优化、查询级架构选择和图约束调度基线相比，TROVE 在质量与效率的权衡上表现更好。当结果改变适当的续接路径时，质量提升最大；而在接近饱和的任务上，提前终止可带来显著的效率提升。消融研究进一步表明，复合技能捕获了大部分离线收益，插入能够实现局部修正，后缀替换主要提升效率。这些发现将选择性路径编辑确立为自适应智能体编排的一般原则。

## Abstract
Agents tend to optimize, select, or constrain execution structures before decisive runtime outcomes are observed. However, such pre-execution commitment creates an orchestration bottleneck: when intermediate evidence invalidates the pending continuation, agents must either execute stale steps or replan broadly, compounding errors, wasting computation, and discarding progress. We thus propose Trace-grounded Route Orchestration via Validation and Editing (TROVE), which revises only what runtime evidence invalidates. Offline, TROVE distills evaluated workflow-search traces into atomic and composite skills and an outcome-conditioned transition graph, preserving stable fragments while exposing outcome-dependent decisions. Online, it treats a planned route as provisional: after committing one top-level skill, the controller retains a valid continuation, inserts a trace-supported local response, or replaces only the invalid suffix. Evaluation across code-generation, question-answering, and math reasoning benchmarks with different LLM backbones show that TROVE delivers a stronger quality-efficiency trade-off than existing baselines of dataset-level optimization, query-level architecture selection, and graph-constrained scheduling. Quality gains are largest when outcomes change the appropriate continuation, whereas early termination yields substantial efficiency gains on near-saturated tasks. Ablations further show that composite skills capture most offline benefits, insertion enables local correction, and suffix replacement primarily improves efficiency. These findings establish selective route editing as a general principle for adaptive agent orchestration.

# TROVE 论文详细中文总结

## 1. 核心问题与研究背景

- 现有智能体工作流编排方法（如 AFlow、MaAS、LAS）倾向于在**执行前**就选定或优化好执行结构：
  - AFlow 在数据集级别固定一条最优工作流；
  - MaAS 在查询级别预先选择架构；
  - LAS 在预先定义好的 DAG 图约束下做节点调度。
- 这类“执行前承诺”（pre-execution commitment）造成一个核心瓶颈——**续接失效（continuation invalidation）**：当中间的执行结果（如评测失败、证据缺失、工具报错）使原本计划好的后续步骤变得不再适用时，智能体只有两个极端选择：**执行已经过时的陈旧步骤**（浪费计算、累积错误）或**整体推倒重规划**（丢弃已有前缀计算，产生高昂延迟与 token 开销）。
- 论文用一个 HotpotQA 的例子说明了痛点：原始路径是 Draft → Review → Format，Review 发现草稿中缺少俱乐部别名信息，但 AFlow 仍会继续执行过时的 Format 步骤（无法修复别名缺口），最终得分 0；而 TROVE 通过插入 Revise 修复缺失别名、并替换掉已无必要的 Format 后缀，最终以 Stop 结束，得分 1。
- 核心论断：编排需要一种**自适应的路径验证与最小化编辑**能力——在每次执行边界后验证待定路由，只在**最小的必要范围**内修正。

## 2. 方法论与关键技术细节

### 总体设计理念：规划-承诺分离

- **规划视野（proposal horizon）** 可以是多个技能（planner 一次性给出短路径）；**承诺视野（commitment horizon）** 只锁定一个顶级技能。
- 将预先规划的路由视为**试探性的（provisional）**，随着执行推进、获得新的边界结果后动态修正。

### 离线阶段：经验提取与技能蒸馏

1. **原子技能（Atomic Skills）**：
   - 将 AFlow 的算子包装为标准化原子技能（声明输入、产出、执行状态、重复约束）。
2. **复合技能（Composite Skills）**：
   - 利用 AFlow 在训练集上进行工作流搜索产生的**成对评估轨迹**（相邻候选工作流及对应的分数增量 Δscore、时间增量 Δtime），识别高频复用且内部稳定、构成一致子目标、具备独立输入输出契约的片段，封装成复合技能。
   - 若某中间结果可影响后续顶层决策，则**不允许**封装进复合技能（保持边界暴露给控制层）。
3. **技能转移图（Skill Transition Graph）**：
   - 将结果依赖（outcome-dependent）的连续关系显式建模为四元组：τ = (s, e, c, g)，其中 s 为完成的技能、e 为观察到的边界事件、c 为边界特征摘要、g 为支持的下一个技能。
   - 转移边来自**已评估的局部工作流修改**（而非简单共现），内部标注分数与时间变化作为离线比较证据，不作为在线路由的直接输入。

### 在线阶段：保留–插入–替换（Retain–Insert–Replace）

- 在线执行可表述为循环：
  1. Planner 给出路径 R₀ = (s₁, …, sₖ)；
  2. Controller 只执行**第一个（头部）顶级技能** st，观察输出 oₜ；
  3. 基于 oₜ 检查挂起的后缀 Qₜ，决策：
     - **终止**：任务已完成，丢弃后缀；
     - **Retain（保留）**：待续技能仍然有效，直接执行，避免额外 LLM 路由调用；
     - **Insert（插入）**：转移图查找到 gt（返回支持的局部修复/测试/验证等技能），将其置于后缀之前：Rₜ₊₁ = (gt) ⊕ Qₜ。适用于即时局部失配、但下游目标意图不变的情况；当 Qₜ 为空时等价于路径扩展；
     - **Replace（替换）**：当无法查找到支持（gt = ⊥）、证据不明确、或需要对续接方向做更广修改时，用 LLM replanner 重新生成**有界替换后缀**：Q̂ₜ = Replan(x, oₜ, Hₜ₊₁, Qₜ, S; gₜ)，Rₜ₊₁ = Q̂ₜ。
  4. 重复“执行—观察—校验/编辑”直到生成最终答案或触达步骤/重复/无进展约束。

- 核心特征：**只编辑未执行部分**，保留已执行的合法前缀及其产物（如草稿、测试结果、中间推理），不做整体重跑。

### 全流程架构总结

- 以训练集中 AFlow 留下的搜索轨迹作为经验来源（而非仅保留最终选中的工作流）；
- 用“原子技能 + 复合技能 + 转移图”三种结构组织可复用能力；
- 以“commit only head”“Retain/Insert/Replace”三种粒度控制在线修正行为；
- 形成一种介于“完全重规划”与“逐步逐节点叫号”之间的中间策略。

## 6. 主要结论与发现

- **总体效果**：18 个 backbone-benchmark 组合中 TROVE 在 15 个取得最佳或并列最佳任务分数；在 16 个取得最短在线时间。
- **相对 AFlow**：
  - 分数提升出现在 16 个设置（0.12–31.37 个百分点）；
  - 时间下降出现在 16 个设置（降低 2.9–86.7%）。
- **相对 MaAS**：17 个设置提高或持平分数（最高提升 46.27 点）；18 个全部降低时间（降幅 6.1–94.6%）。
- **相对 LAS（6 个代码类设置）**：5 个设置分数提高 1.47–7.03 点；6 个设置时间全部下降 37.3–63.9%。
- **任务差异**：
  - 在困难的多步推理任务（MATH）上，由于中间结果更容易推翻后续步骤，质量收益大（6.79 点）且时间显著下降（62.1%）；
  - 在高饱和任务（GSM8K）上，质量提升有限但**提前终止带来大额时间节省**；
  - 在 QA 任务（DROP / HotpotQA）上，难度主要来自证据抽取与长上下文，而非路径结构不稳定，因此增益较小。
- **编辑类型分布**（DeepSeek-V4-Flash）：
  - HumanEval 有较高修正性编辑率（54.2%）——体现“失败驱动的修正需求”；
  - MATH（98.97%）与 GSM8K（100%）的编辑几乎都是“早期产出即终止”造成的**修剪型编辑**（计入 Replace）；
  - MBPP（5.87%）、DROP（7.75%）、HotpotQA（2.88%）通常保留初始路径。
- **消融结论**：
  - 去掉全部离线能力后准确率下降 14.51 点、时间增加 9.26 分钟；
  - 去掉复合技能后损失几乎与去掉全部离线结构相近（−13.74 点），说明**复合技能承担了大部分离线收益**；
  - 去掉 Insert 后准确率降低 9.93 点、时间增加 14.74 分钟，说明**局部修复依赖图支持的有界插入**；
  - 去掉 Replace 后准确率仅下降 1.53 点但时间上升 15.79 分钟，表明**后缀替换的主要作用是效率提升**（快速终止/跳出无望路径）而非精度提高。

## 7. 优点

- **问题定义准确且有新意**：把“中间证据使残留步骤失效”概括为 continuation invalidation 并系统化研究，找准了现有三大类方法（离线优化、执行前查询级选择、固定图内调度）之间的空白。
- **“最小足够范围修正”的归纳清晰**：只替换无效后缀、保留合法前缀，保留了已完成的中间工件，能同时改善质量、延迟和 token 消耗。
- **有效利用已有搜索轨迹**：不像 AFlow 只保留最后一条选出的工作流，而是把搜索过程产生的成对评估作为经验蒸馏来源；用 (s, e, c, g) 转移边记录的不是“序列共现”而是“带分数证据的经验”，设计严谨。
- **复合技能的封装原则具体且可操作**：以“内部是否稳定、是否有明确子目标、是否会被外层结果影响”作为能否打包的判据，逻辑自洽。
- **在线控制器设计克制且可解释**：Retain 防止过度反应，Insert 处理局部修复，Replace 保留全局重规划能力；通过对图查找失败（gt=⊥）做条件触发控制 replan 频率。
- **实验覆盖面在同领域论文中较完整**：3 个表 + 额外编辑率统计与消融，涵盖多任务、多骨干、多方法粒度；时间和 token 指标回应了效率问题，不止于质量单一维度。

## 8. 不足与局限

- **算力信息披露不足**：没有给出离线阶段（工作流搜索、复合技能挖掘、转移图构建）所需的 GPU 型号与时数；对于希望复现或估算总成本的读者不便。
- **消融实验范围偏窄**：仅在 HumanEval + Qwen3-8B 上做消融。“复合技能占离线收益大部分、Replace 主要提升效率”等结论是否在 MATH/QA 或强模型底下成立未经验证。
- **缺少统计稳健性度量**：多组在线运行的标准差、显著性检验（如配对检验）未报告；以单次运行为主；对随机性敏感的在线编排方法而言这是评估完整性的短板。
- **LAS 基线只覆盖代码类 6 个设置**：TROVE 在 QA 与数学任务上缺少来自最贴近在线类基线的比较，限制了“优于图约束在线调度”这一结论的推广范围。
- **任务类型不够宽**：没有覆盖多轮对话、工具使用 (tool-use)、机器人控制、复杂 Agent 交互等典型长程操作场景；TROVE 的“边界结果”概念在这些场景中需要新的形式化适配。
- **可能的风险：对轨迹质量的依赖**：离线蒸馏依赖训练分区上 AFlow 搜索轨迹的质量与覆盖度

“离线蒸馏依赖训练分区上 AFlow 搜索轨迹的质量与覆盖度”——若该搜索未覆盖足够多样的失败模式或边界事件，转移图与复合技能库可能出现空洞（missing edges），导致在线阶段更频繁地回退到 LLM replanner，削弱图查找带来的效率收益；且论文未讨论在训练分区搜索质量不足时的降级策略。

- **对基准选择的解释不足**：为什么选择 AFlow 作为唯一的离线经验来源而非同时使用 MaAS 或 LAS 的轨迹？如果经验来源的搜索策略本身存在偏向（如对某类任务的路径偏好），蒸馏出的转移图是否会继承这种偏置并限制 TROVE 的上限？论文对此缺乏敏感性分析。
- **“插入”与“替换”的边界判定在呈现上偏粗**：controller 何时判定“图查找得到 gt”与“gt=⊥”（从而触发 replan）属于二值决定，但现实中存在中间情况：候选 gt 有多个且彼此冲突、或 gt 部分满足当前上下文。论文将这类情况归入 Replace，看似以 replan 作为安全兜底——但该兜底的触发语义、频率与质量对 LLM replanner 的提示设计高度敏感，文中未展开 replanner 的提示模板或边界判定规则的消融。
- **缺少失败案例的事后分析**：虽然论文在开篇用 HotpotQA 的一正一反实例说明了动机，但未系统分析 TROVE 在 18 个设置中仍输掉的几个设置（如相对 MaAS 少数持平、与 AFlow 持平但耗时更长的情况）的具体失败模式，使读者难以判断当前设计的残余瓶颈究竟在控制粒度、技能覆盖还是规划器质量。
- **长尾在线成本的测算口径**：论文将离线搜索统一处理为“一次性成本”，但复合技能挖掘与转移图构建本身也依赖 AFlow 在工作流搜索中大量调用 LLM；对于一个只希望部署 TROVE 的新任务来说，这部分成本不会“消失”，只是转移到了训练阶段。论文未将离线成本折算到“单样本摊销成本”中，也未说明离线阶段在 6 个基准上各花了多少 LLM 调用量级。

## 9. 可能的改进方向与展望

### 方法论层面

- **构建闭环“execute–verify–repair–learn”自我更新机制**：当前 TROVE 的转移图在测试期完全冻结，无法吸收在线产生的新边界后续恢复经验。可以让“Replan 成功完成任务的路径”回流为新的转移样本，用在线时离线经验的可比较证据，持续扩充 (s, e, c, g) 边库，但要小心循环验证与 OOD 污染问题——建议只吸收与既有边目标一致、且经 offline 评估确实不降级的样本。
- **引入不确定性感知（uncertainty-aware）的边界事件表示**：当前每条转移边使用边界特征摘要 c 作为触发，没有显式建模该边界事件本身的概率。若能对边界事件（如“测试第一次失败”“证据缺失”“生成动作被中止”）赋予置信度，Controller 可以在图匹配时不仅比较语义相似度，还结合事件发生的可靠性，避免把偶然的一次性失败泛化为系统性转移。
- **分层承诺视野（hierarchical commitment）**：当前 commit horizon 固定为“一个顶级技能”。对于任务片段内部复杂但顶层决策空间大的场景，可动态扩大缩小承诺粒度——高置信前缀多承诺几个技能以减少验证开销，结果方差大时退回更小承诺——从而在“路由调用频率”与“陈旧步骤风险”间找到更优平衡。
- **与自适应 token 预算规划结合**：Insert/Replace 决策本身只决定“改不改路径”，未显式考虑剩余预算。可将 token 剩余量与时间剩余量作为后缀重规划的约束条件输入 planner，使 Replace 生成的候选后缀长度随剩余预算自适应缩放，防止当逼近超时边界时 replanner 仍展开过长路径。

### 实验层面

- **为转移图匹配过程引入负样本约束的小型验证**：抽样自然执行轨迹中出现的“部分匹配但语义失败”事例，测试当前图匹配是否会错误命中（false hitting）并导致无谓 Insert。若发现误命中率偏高，考虑为 c 增加否定式条件（如“但未出现 X”），这是可验证、可消融的具体增强点。
- **做跨任务迁移试验**：在一个数据集（如 HotpotQA）上构建转移图，直接在另一个同类型数据集（如 DROP）上部署并测量冻结结构带来的性能损失，借此检验 (s, e, c, g) 表达是否具有任务间迁移性——这是“技能图可复用性”主张最直接的证据。
- **报告运行多次的标准差并提供子集级收益分布**：至少对核心声称在 3 个代表性设置（HumanEval、MATH、HotpotQA）上取 5 次运行按均值 ± std 报告结果，并以 paired test 检验“TROVE 优于 AFlow/MaAS”的显著性；同时给出按样本难度分层（易 / 中 / 难）的编辑率、时间节省分解，帮助判断收益来源是实现后验修正还是大量提前终止。
- **展示结构化能力边界上的失败模式**：自定义少数“需要在步骤中途更换工具集/切换上下文来源”的合成关卡，并在“只允许 Replace、禁用 Retain”“只允许 Retain、禁用 Insert/Replace”等极限配置下运行，直观暴露出 Controller 在能力边界处对三个原语的依赖程度。

## 10. 总结性总评

TROVE 的贡献本质上落在两个层面：**概念层面**揭示出“边界结果可能同时否定‘旧路径的延续’并开启‘新路径的机会’”，因此编排问题的核心不是选择一个适配粒度（数据集级、查询级、还是节点级），而是**在执行边界动态地做路径验证与最小必要修正**；**工程层面**则以“原子技能 + 复合技能 + 转移图”作为离线先验、以“Retain–Insert–Replace”为在线控制原语，将前述概念实现在一个清晰、可解释且几乎不增加额外路由调用次数的系统内。相比完全离线静态工作流，它避免了陈旧步骤的空气执行；相比逐步逐节点的完全动态选择，它以离线转移边代替高频 LLM 在线路由，保留了可读性与可控性。

在主实验的 18 个 backbone-benchmark 组合中，TROVE 在 15 个取得最佳或并列最佳质量、16 个取得最短时间，这与其“只修改无效后缀”的设计目标一致——质量的改善主要源自 Insert 修复语义断点与 Replace 及时终止无效路径，时间的节省主要源自提前终止与图匹配驱动的 Retain（避免重复 LLM 路由）。

但论文在**消融范围的宽度、统计稳健性的深度、算力信息披露的透明度、以及 LAS 基线缺位导致 QA/数学任务缺少在线类对照**等维度上存在明显可得改进。当前结论更宜读作“在 3 个任务域 × 3 个薄弱骨干模型上、单次测评下，TROVE 对 AFlow/MaAS 有全面且显著的效率和精度优势，对 LAS（在代码数据上）优势成立”，而在“最优 LLM、多次运行、真实部署与扩展场景”之间仍留有数据真空。整体而言，作为对“后验感知的限定路由编辑”问题的系统化首次回答，TROVE 完成度与启发性兼具，值得作为执行后自适应编排方向的参照基准。
