## 摘要
计算机使用代理能够在图形界面中执行日益复杂的任务，但其交互经验通常是短暂的：从一次运行中获取的程序性知识不会被系统地保留、精炼并在后续任务中复用。现有的技能库提供了外部程序性知识，然而，与未使用技能库的同一代理相比，这些技能库的增量价值，以及它们在重复交互下的纵向动态，仍未得到充分表征。我们提出了一种在线技能进化框架，将交互轨迹和评估者反馈转化为一个持久的、带版本的可复用程序库。每次迭代都针对冻结的库快照执行，而由证据引导的技能更新在后续迭代中可用，无需更改模型参数。我们将完整的进化库系统与配置匹配的空库对照组，在四个OSWorld应用领域、相同的固定动作生成与GUI接地栈、任务集和迭代范围内进行了比较。在五次迭代的空库预热之后，完整系统在所有四个观察到的领域运行中均获得了更高的预热后平均评估者分数，平均差异范围为5.7至18.6个百分点，并表现出依赖于领域的时序稳定性。在GIMP中，来源感知分析揭示了跨源任务边界的检索和修订更替，即重复接受的编辑未能恢复源任务。这些发现将进化技能库表征为可审计的共享程序性记忆，能够改进固定的计算机使用栈，同时表明其益处是有条件的，且重复修订并不能保证恢复。代码发布于https://github.com/LongtaoHu/Skill-Evo4GUI。

## Abstract
Computer-use agents can execute increasingly complex tasks in graphical interfaces, but their interaction experience is typically transient: procedural knowledge acquired from one rollout is not systematically retained, refined, and reused in later tasks. Existing skill libraries provide external procedural knowledge, yet their incremental value over the same agent operating without skills, as well as their longitudinal dynamics under repeated interaction, remain insufficiently characterized. We present an online skill-evolution framework that converts interaction trajectories and evaluator feedback into a persistent, versioned library of reusable procedures. Each iteration executes against a frozen library snapshot, and evidence-guided skill updates become available in subsequent iterations without changing model parameters. We compare the full evolving-library system with a configuration-matched empty-library control across four OSWorld application domains under the same fixed action-generation and GUI-grounding stack, task sets, and iteration horizons. Following a five-iteration empty-library warm-up, Full attains a higher post-warm-up mean evaluator score in all four observed domain runs, with mean differences ranging from 5.7 to 18.6 percentage points and domain-dependent temporal stability. In GIMP, provenance-aware analysis reveals retrieval across task-of-origin boundaries and revision churn, where repeated accepted edits fail to recover the originating task. These findings characterize evolving skill libraries as auditable, shared procedural memory that can improve a fixed computer-use stack, while showing that their benefits are conditional and repeated revision does not guarantee recovery. Code is released at https://github.com/LongtaoHu/Skill-Evo4GUI.

## 2. 方法论：核心思想、关键技术细节与流程
论文提出了一个**在线技能演化框架（Online Skill-Evolution Framework）**，核心设计思想是**将只读执行与写权限演化分离**，由四个主要阶段组成（对应文中图1）：

### 2.1 运行时执行（Runtime Execution）与渐进检索
- 在迭代开始时，当前实时技能库被导出为**只读快照（S_t）**，同一迭代中的所有任务都基于该冻结快照执行。
- 固定Executor（动作生成模型）负责规划和选择工具调用；对于坐标相关动作，由固定Grounding模型将自然语言描述映射为像素坐标，通过pyautogui执行。
- **渐进检索（Progressive Retrieval）**：运行时只把每个SKILL.md的名称与描述解析为Markdown目录放在Executor提示中；当需要时由执行器调用 `get_skill(name, reasoning)` 获取完整技能正文，检索过程为只读，不会向当前迭代暴露本次新提交的变更。

### 2.2 轨迹抽象（Trace Abstraction）
- 原始交互轨迹细节过多，Extractor将其转化为**结构化事实（F_t）**，包括任务摘要、结果、步骤级记录、聚合模式、技能调用观察。
- 轨迹证据来源包括：执行动作、截图、官方评估器分数、后置条件检查、以及**遥测记录**（唯一权威记录技能调用信息）。
- 评估器分数优先于模型自我陈述，遥测中缺失的调用会被删除，遗漏的调用会被补回，以保证事实的可靠性与来源可追溯。

### 2.3 在线技能演化（Online Skill Evolution）与版本化持久化
- Proposer基于同一任务最近至多5次迭代的结构化事实历史，发出决策提议：`create_new` / `edit_existing` / `delete_existing` / `no_op` / `unresolved`。
- Coordinator执行约束与规则：
  - 创建新技能需至少5次观察；
  - 重复创建名或超过大小门限的编辑将降级为no-op；
  - `unresolved` 仅在证据窗口包含至少2次失败时才被接受。
- Skill Builder根据高层意图生成**完整的新版SKILL.md**（编辑时为全量替换而非直接文本补丁）。
- 每个接受的变更以**独立Git提交**写入实时库，保留修订历史与贡献任务ID；仅下一迭代快照开始生效。

### 2.4 来源追踪（Provenance Preservation）
- 技能的**源任务（origin task）**在创建时固定；每次接受的修订记录贡献任务与对应版本；每次检索记录消费任务、迭代、交付版本及下游结果关联（成功/失败/部分进展/无法确定）。
- **跨源检索（cross-origin retrieval）**：当消费任务 ≠ 源任务时即为跨源检索。
- 本文强调：该设计支持追踪**复用与修订历史**，但不做因果归因（一次rollout可能检索多个技能，结果可能受其他因素影响）。

## 6. 主要结论与发现
1. **增量价值得到初步验证**：Full（演化技能库）在四个域的预热后（t≥5）平均评价分**全部高于**空库对照，差异为 **+5.7至+18.6个百分点**，且在不同域呈现**非均匀、非单调**的时间动态：
   - GIMP：+5.7pp（最小，反复穿越）；
   - VLC：+18.6pp（最大，稳定拉开）；
   - Writer：+11.8pp（但预热期已含+9.1pp固有偏置）；
   - Thunderbird：+12.4pp（预热期−6.7pp，后期扭正）。
2. **技能被跨任务复用**：GIMP中被调用的技能有 **43.3%为跨源检索**（消费任务≠源任务），说明库在实际交互中被当作**共享程序性记忆**而非仅任务专属档案；但这是观测性关联，非因果验证。
3. **重复修订不保证恢复任务**：GIMP中"背景透明化"任务家族出现 **修订震荡（revision churn）**——`gimp-add-alpha-channel` 经历多次接受的编辑，但源任务在35次迭代中仅成功 **2次（5.7%）**，说明失败证据虽然持续驱动修改，但由于技能只提供文本程序性指引、GUI动作仍过固定执行栈，技能修改**无法修复深层执行或定位故障**。
4. **总体定位**：演化技能库可以作为一种有条件的、可审计的共享适应层，价值**依赖领域与场景**，并非普遍、有保证的提升。

## 7. 优点与亮点
- **干净的问题切割**：在执行器与接地模型**完全固定**的条件下研究外部记忆的贡献，避免了"技能演化"与"模型微调/上下文内适应"混淆。
- **条件匹配对照设计**：Full与Empty保持同一运行时接口（包括目录提示和get_skill工具），唯一变量就是是否允许技能库累积，归因逻辑明确。
- **迭代冻结快照机制**：保证演化阶段提交的变更不会污染当前迭代的正在执行轨迹，执行与演化解耦，时序关系清晰可信。
- **来源追踪（Provenance）思想**：以Git提交记录技能从创建、修订到检索的全生命周期，不只是看最终分数；能区分"同源检索"和"跨源检索"，观察到单一聚合分无法揭示的纵向动态。
- **客观呈现负面结果**：作者明确报告**修订震荡**现象（反复编辑不恢复任务）、**Writer域预热偏置**和**跨源检索非因果性**，没有夸大技能库收益，体现科学诚信。
- **对审查者友好的开放协议**：公开完整代码仓库，提高可复现性。

## 8. 不足与局限
### 8.1 实验层面的局限
- **单次运行**：每条件-域仅一条轨迹，随机性未被估计，无置信区间、无显著性检验、不能排除偶然性。
- **预热期不平衡**：5轮空库运行期间Full与Empty已经出现分离（如Writer +9.1pp、Thunderbird −6.7pp），预热后差异不等于纯粹的技能因果效应。
- **重复任务集**：衡量的是"对同一批任务的增量适应"，而非模型对新任务的泛化能力或技能迁移能力。
- **深度分析仅覆盖GIMP**：跨源检索与修订震荡分析只在GIMP域进行，其他域的技能水平动态未知。
- **无消融实验**：缺少对技能创建/编辑/删除/检索各部分价值的独立量化。

### 8.2 方法本身的局限
- **观测性而非因果性**：遥测记录的是"检索了什么"，不是"技能多大程度影响了后续动作和结果"；多次检索、多因素影响下无法确定单个技能的因果作用。
- **文本指导的瓶颈**：技能仅提供SKILL.md文本程序指引，GUI实际动作仍由固定Executor+Grounding完成，因此**无法修复底层的接地（grounding）定位错误或动作生成错误**——修订震荡正是这一瓶颈的体现。
- **串行演化的顺序依赖**：同一批次内任务按固定顺序逐个处理，后面的提议可看到前面的提交，演化结果依赖处理顺序，且无自动整合（consolidation）机制或回滚机制。
- **缺少技能遵守度测量**：有调用统计，但未直接验证Executor是否真正遵循返回程序的内容或是否在适当时候克制不用技能。

### 8.3 其他
- **OSWorld参考分仅为语境参考**，其官方成绩背后的模型版本、执行栈与本文系统中配置并不相同，不能直接横向比较。
- **算力与成本信息缺失**（参见第4节），不利于社区评估方法的经济性与实用阈值。
- 应用生态局限于Linux桌面上的4个应用，未涉足Windows/macOS、网页环境或移动界面。
