## 摘要
从经验中学习对于开发能力强、能自我改进的大语言模型（LLM）智能体至关重要。现有方法通常通过反思、记忆、规则或技能从累积的轨迹中提取知识。然而，在现实环境中，智能体不断遇到新任务，通常只有一次改进机会。这些执行过程会产生丰富但高度嘈杂的上下文，将广泛有用的教训与特定任务的细节纠缠在一起。关键的是，先前的工作很少在复杂的现实任务上验证其有效性，或隔离改进的潜在驱动因素。为解决这些不足，我们提出了在线工具链学习（online harness learning）的框架，即一个冻结的智能体通过连续任务中持续更新结构化工具链来改进。该框架使我们能够通过所提出的Evo-Harness系统性地研究关键的自改进因素。其核心是从上下文到工具链的技能编译（context-to-harness skill compilation），将嘈杂的单次执行过程蒸馏为可复用的技能工具链，以实现跨领域和主题级别的适应。为展示一次性技能编译的有效性，我们在五个现实基准（TerminalBench2、SWE-bench、CL-Bench、-bench、WebArena-Infinity）上进行了评估。我们广泛的分析证明了Evo-Harness的有效性，并为LLM智能体如何有效进行实时学习提供了原理性理解。我们的代码可在https://github.com/A-EVO-Lab/a-evolve/tree/release/evo-harness获取。

## Abstract
Learning from experience is critical for developing capable, self-improving large language model (LLM) agents. Existing methods typically extract knowledge from accumulated trajectories via reflection, memory, rules, or skills. However, agents in realistic environments continuously encounter novel tasks, often offering only a one-shot opportunity to improve. These executions yield rich but highly noisy contexts, entangling broadly useful lessons with task-specific artifacts. Critically, prior works rarely validate their effectiveness on complex real-world tasks or isolate the underlying drivers of improvement. To address these gaps, we formulate online harness learning, where a frozen agent improves by continually updating a structured harness across sequential tasks. This formulation enables a systematic study of key self-improvement factors through our proposed Evo-Harness. At its core, context-to-harness skill compilation distills noisy, single-shot executions into reusable skill harnesses for cross-domain and topic-level adaptation. To demonstrate the efficacy of one-shot skill compilation, we evaluate across five realistic benchmarks (TerminalBench2, SWE-bench, CL-Bench, -bench, WebArena-Infinity). Our extensive analysis demonstrates the effectiveness of Evo-Harness and provides a principled understanding of how LLM agents can effectively learn on the fly. Our code is available at https://github.com/A-EVO-Lab/a-evolve/tree/release/evo-harness.

### 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：LLM 智能体在现实环境中会持续遭遇全新任务，但每次执行通常只有一次改进机会。现实执行过程产生的上下文高度嘈杂，广泛有用的经验与任务特有细节（如特定命令、错误信息、工具痕迹）纠缠在一起，导致智能体难以自动提炼可复用的知识。现有经验学习方法（如反思、记忆、技能）大多依赖离线累积轨迹进行挖掘，很少能在 **单次、在线、连续** 的执行流中有效工作，也缺乏在复杂真实任务上的验证及其改进驱动因素的隔离分析。

- **整体含义**：作者提出将智能体改进过程形式化为“在线工具链学习”（online harness learning），即保持求解模型冻结，通过持续更新一个外部结构化的“工具链”/“技能库”，使智能体在任务流中不断自我提升。这不仅是一种新方法，更是把工具链作为“分析透镜”，系统研究 LLM 智能体如何即时学习的原理。

### 2. 方法论：核心思想、关键技术与算法流程

- **核心思想**：将单次执行的嘈杂上下文“编译”为结构化的可复用技能工具链（harness），用于指导未来任务中的规划、动作、验证与恢复。区别于直接检索过去案例（experience reuse），Evo-Harness 将经验抽象为通用的跨任务模式（cross-task patterns）与特定主题的操作流程（task-type procedures）。

- **关键技术细节**：
  - **两阶段编译管道**：
    - **执行反思（Execution Reflection）**：仅当任务失败或收到负面反馈时，对执行上下文（输入、轨迹、输出、反馈）进行总结，生成候选记忆，每个记忆由 `(lesson, trigger, evidence, scope_hint)` 组成。
    - **工具链进化（Harness Evolution）**：一个进化学器（evolver）接收候选记忆与当前工具链，执行 ADD / MERGE / REVISE / SKIP 四种编辑操作，将候选信号过滤、合并、修订后写入工具链。
  - **双级别技能**：
    - 跨任务模式（Cross-task patterns）：跨多个任务提取的共享操作结构；
    - 任务类型流程（Task-type procedures）：针对特定任务格式/领域/界面的本地化操作知识。
  - **模块化设计**：求解器（solver）、进化学器（evolver）、反馈源、初始工具链互相解耦，便于系统剖析各因素对改进的影响。

- **算法流程（文字说明）**：
  1. 对于每个任务批次，求解器根据当前工具链检索相关技能条目并注入任务上下文；
  2. 冻结的求解器执行任务，产生执行上下文（输入、轨迹、结果、反馈）；
  3. 对失败/负反馈执行进行反思，生成候选记忆；
  4. 批次结束后，进化学器编译任务类型流程与跨任务模式，更新工具链；
  5. 更新后的工具链用于引导后续批次，如此循环迭代。

### 3. 实验设计：数据集、基准与对比方法

- **基准数据集**（覆盖多类智能体能力）：
  - **WebArena-Infinity**（80个任务）：Web 导航/UI 状态验证；
  - **TerminalBench2**（89个任务）：命令行/脚本/系统管理；
  - **SWE-bench Lite**（300个任务）：真实 GitHub 软件工程问题；
  - **CL-Bench**（1899个任务）：自适应推理（知识推理、实证发现、程序执行、规则应用）；
  - **τ-bench / TAU-Bench**（165个任务）：航空与零售领域的工具调用。

- **对比方法**：No-Evolve（无进化基线）、AWM（工作记忆复用）、Dynamic Cheatsheet 及其变体 DC-Cu / DC-RS、Evo-Memory、ACE（上下文优化）、XSkill（经验与技能分离的持续重用）。

- **默认求解器**：Claude Opus 4.6；另在多模型泛化实验中测试了 Opus 4.7、Opus 4.5、Kimi-K2.5、GPT-OSS，以及 Claude Sonnet 4.5 等。

### 6. 主要结论与发现

- **整体有效性**：Evo-Harness 在全部五个基准上均优于 No-Evolve 和现有经验/记忆/技能基线，且在 TerminalBench2 上提升最大（+10.11），说明工具链进化对具有可复用程序性结构的任务最有效。
- **外部经验复用并非自动有益**：部分基线在部分基准上甚至低于 No-Evolve，说明盲目复用嘈杂经验可能有害；有选择的编译比直接累积更有价值。
- **跨模型泛化**：由较弱模型（Claude Sonnet）在训练集上进化出的技能，可以迁移到较强求解器（Opus 4.7）并持续提升表现；在线更新比离线迁移更好（+1.6）。
- **配对效应**：同一模型既当求解器又当进化学器并非总是最优；跨模型进化可以生效，但前提是求解器足够强大以理解和遵循该指导。
- **反馈关键性**：自生成的自我判断反馈会误导进化（甚至低于 No-Evolve）；环境提供的最小信号（通过/未通过）与标准诊断反馈（错误追踪、测试输出）更可靠。CL-Bench 上丰富诊断更好，SWE-bench 上最小信号可能更利于泛化。
- **双级技能互补**：跨任务模式在 SWE-bench 更重要，局部任务类型流程在 CL-Bench 更重要，两者结合为最佳。

### 7. 优点：方法与实验亮点

- **问题设置精准**：明确切中现实约束（单次执行、嘈杂上下文、连续任务流），区别于大多数离线经验学习框架。
- **“编译”而非“检索”**：通过技能编译将执行上下文提炼为可操作且具有触发条件的指导，避免了原始轨迹的噪音和过拟合。
- **双级技能设计**：跨任务普遍模式与任务类型本地流程互补，既保留可迁移知识又过滤任务特有噪声。
- **工具链作为可解释分析对象**：通过消融、配对实验、反馈对比等方式系统分离了进化设计、反馈类型、转移条件的独立贡献，使分析具有科学解释力。
- **实验覆盖面广**：横跨 Web、CLI、软件工程、推理、工具使用五类真实场景，且在主结果外进行了丰富诊断分析。
- **可复现性**：固定种子、统一评估协议、开放代码与进化后的技能库，降低复现门槛。

### 8. 不足与局限

- **场景覆盖有限**：仅研究了基于文本的单智能体体系，未涉及多智能体系统、具身智能体（embodied agents）或涉及物理交互的环境。
- **工具链形式受限**：工具链仅用自然语言指导实现，未研究可执行代码技能、结构化程序或检索增强等替代格式，可能限制了表达力与自动化程度。
- **模型依赖性与成本**：较弱的求解器从工具链进化中收益有限，甚至在部分类别（如 EDS、RSA）出现退化；全部实验依赖商业 API，总成本约10万美元，可负担性和可扩展性存疑。
- **无法做到单技能因果归因**：论文承认，展示的改进案例并非单技能因果消融——多个技能可能同时注入，部分基准未记录每次注入的具体技能，因此难以严格归因于某一个技能条目。
- **潜在偏差风险**：自生成反馈实验说明无外部依据的自我判断可能引入误导性更新；此外，反馈粒度与任务匹配程度（如 SWE-bench 中最小反馈偶尔优于标准反馈）表明，最佳反馈策略仍需针对具体场景设计。
