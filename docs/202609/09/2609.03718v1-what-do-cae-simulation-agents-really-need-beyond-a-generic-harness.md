## 摘要
计算机辅助工程（CAE）仿真是工程领域中规模最大、要求最高的领域之一，其中设置诸如OpenFOAM、FEniCS或COMSOL等求解器需要真正的专业知识。大型语言模型（LLM）代理有望将自然语言请求转化为可运行的仿真，而最近的CAE代理增加了仿真专用机制：多代理分解、领域检索和脚本化反思。这些机制适合较弱的基座模型；现代框架已经提供了多轮推理、工具使用和执行反馈。我们探究CAE仿真代理在通用框架之外还需要什么。在信息访问和修复预算固定的情况下，单代理框架能够媲美甚至超越多代理专业系统（FoamBench 96.4% vs. 88.2%）。消融实验将这一结果归因于框架已具备的能力：带执行反馈的修复将FoamBench从无修复轮的71.8%提升到96.4%，而脚本化反思没有带来任何增益。唯一仍然有帮助的输入是以求解器教程形式提供的领域知识，这是我们测得的最大提升（从80.9%到96.4%）。

## Abstract
Computer-aided engineering (CAE) simulation is among the largest and most demanding areas of engineering, where setting up a solver such as OpenFOAM, FEniCS, or COMSOL takes real expertise. Large language model (LLM) agents promise to turn a natural-language request into a working simulation, and recent CAE agents add simulation-specific machinery: multi-agent decomposition, domain retrieval, and scripted reflection. That machinery suited weak base models; modern harnesses already supply multi-turn reasoning, tool use, and execution feedback. We ask what a CAE simulation agent still needs beyond a generic harness. With information access and repair budget held fixed, a single-agent harness matches or beats multi-agent specialized systems (FoamBench 96.4\% vs.\ 88.2\%).   Ablations trace this to capabilities the harness already provides: execution-feedback repair lifts FoamBench from 71.8\% with no repair round to 96.4\%, while scripted reflection adds nothing. The one input that still helps is domain knowledge supplied as solver tutorials, our largest measured gain (80.9\% to 96.4\%).

### 一、论文的核心问题与整体含义

- **研究背景**：CAE仿真（如OpenFOAM、FEniCS、COMSOL、PyChrono等）是高度依赖专家经验与数值求解知识的工程领域。近年来的CAE专用LLM智能体普遍引入三类"仿真专用机制"：多智能体角色分解（planner/writer/runner/reviewer）、基于检索的领域知识注入（domain RAG）、以及脚本化反思（scripted reflection），典型系统如Foam-Agent、MetaOpenFOAM、ChatCFD、MCP-SIM等。
- **核心问题**：这些专用机制是早期弱基座模型时代的产物。如今通用编码智能体框架（如Claude Code、Codex CLI等）已原生具备多轮推理、工具调用与执行反馈修复等能力，作者追问：**CAE仿真智能体在通用框架之外，究竟还真正需要什么？**
- **整体含义**：通过受控对比发现，专用系统所宣称的多数增益实际上可由通用框架提供的能力覆盖，真正的瓶颈在于**领域知识的注入方式**——以求解器教程形式提供知识是测得的最大增益来源。这提示后续研究应将工程精力投向数据与评测基准建设，而非堆叠脚手架架构。

### 六、论文的主要结论与发现

- **核心结论一：单智能体通用框架可超越专用多智能体系统**。在信息访问与修复预算受控的条件下，Claude Opus 4.6的Direct Baseline在FoamBench上达到96.4%，高于专用系统公布的88.2%；MCP-SIM上四种通用配置全部100%，超过专用系统的91.7%；其余基准上至少一种配置追上或超过原专用系统数字。
- **核心结论二：执行反馈修复是决定性能力，且由通用框架原生提供**。FoamBench上"无修复"（R≤1）仅0.9%，允许一次网格+一次求解（R≤2）即跃升至71.8%，R≤10时达96.4%。这说明绝大多数成功来自"先跑再修"的执行闭环——这正是编码agent harness的核心机制，无需任何CAE专用设施。
- **核心结论三：脚本化反思无额外价值**。在FoamBench上，加入显式自省指令后成功率仍为96.4%（106/110），与不加完全持平；模型本身已具备反思行为。
- **核心结论四：领域知识（教程）是通用框架之外最大的增益来源**。FoamBench上"无教程→必读教程"带来+15.5个百分点的提升（80.9%→96.4%），是全文测得的单项最大增益；且"可选教程"即可恢复约2/3的差距。该增益源自正确的领域材料是否到达模型，而非材料如何被检索与包装。在SimBench上只带来+6.7点，在MCP-SIM上无提升（已饱和）——效应高度依赖任务缺口。
- **核心结论五（指向未来）**：CAE智能体领域当前真正稀缺的是**标准化、代表性、具区分度的benchmark**，需要区分"代码能跑"与"物理结果正确"，并提供跨系统可比的多轮文档访问与任务演化设定。

### 八、不足与局限

- **实验统计强度不足**：所有实验均为单次运行，无并行重复、无方差报告，文中对此坦诚承认。在MetaOpenFOAM v1、MCP-SIM、FEABench等小样本suite上，一两例的差异已落入噪声内。
- **专用系统未在相同基座下重跑**：对比列引用的是原论文公布数字（基座模型多为GPT-4o/旧版Qwen等），非同一模型时代，通用框架的进步部分应归因于更强的基座而非脚手架缺失，这项混淆无法据此文分离。
- **评测标准本身偏弱**：多数benchmark以"能跑到End/收敛"或LLM裁判为准，仅FoamBench和FEABench有数值级的物理验证（且FoamBench上两者差距可达约20个百分点）。以运行成功替代物理正确性可能高估所有方法的真实工程能力。
- **消融范围有限**：反思消融与修复预算消融仅在FoamBench上执行，教程消融只覆盖3个suite；对其他求解器（如COMSOL、OpenSeesPy）是否适用未知。
- **时效快照性**：四组harness-模型组合均为2026年年中的公开商业或快速迭代产品，绝对数值必然随时间漂移；作者认为"领域知识>脚手架"的相对结论更持久，但尚未被更长期数据验证。
- **教程供给的现实限制**："将教程放在上下文中"在PyChrono等教程可用性弱的场景边际贡献有限，而现实中许多工业CAE问题的知识稀缺性更高，通用教程并不能完全替代稀缺的专家经验。
- **未触及物理一致性深水区**：文中的任务多以单行自然语言描述、以官方教程为模板改编而来，尚未触及需要多步模型选择论证、网格收敛性分析、结果物理解读的"真实工业复杂度"任务；作者亦承认这一点。
