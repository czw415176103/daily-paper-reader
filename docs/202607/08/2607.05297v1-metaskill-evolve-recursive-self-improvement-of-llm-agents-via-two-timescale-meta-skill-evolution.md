## 摘要
近期LLM智能体处理越来越长周期、开放式的任务，而外部技能（提供给智能体的可重用程序性知识）进一步扩展了这种能力。然而，固定的手动编写的技能很少是最优的，并且无法适应智能体遇到的任务多样性。自我改进的智能体通过从执行轨迹中重写自己的技能文件来解决这一问题，在具有挑战性的基准测试上取得了显著收益。然而，这种自我演进仍然是非递归的：它只改进了任务技能（智能体做什么），而改进过程（如何改进）是一次性编写的并保持不变。我们引入了MetaSkill-Evolve，一个双时间尺度框架，使智能体技能改进成为递归的：每个分支都包含一个任务技能$s$和一个分支本地元技能$m=(ψ,σ,α,π,\varepsilon)$，其五个组件分别参数化改进流程中的分析器、检索器、分配器、提议器和进化器智能体。任务技能在快速循环中演进，而元技能在较慢循环中演进，使用相同的流程应用于自身，无需额外模型或目标。在所有五个流程智能体共享单个冻结骨干的情况下，MetaSkill-Evolve在三个智能体基准测试（OfficeQA、SealQA、ALFWorld）上优于无技能、静态技能和单层次演进基线，分别将原始骨干的保留测试准确率提高了+23.54、+16.09和+1.92个百分点。

## Abstract
Recent LLM agents tackle increasingly long-horizon, open-ended tasks, and external skills, reusable procedural knowledge supplied to the agent, further extend this capability. However, a fixed, hand-authored skill is rarely optimal, and cannot adapt to the diversity of tasks an agent encounters. Self-improving agents address this by rewriting their own skill files from execution traces, yielding meaningful gains on challenging benchmarks. Yet such self-evolution remains non-recursive: it improves only the task skill (what the agent does) while the improvement procedure (how it improves) is authored once and held fixed. We introduce MetaSkill-Evolve, a two-timescale framework that makes agentic skill improvement recursive: every branch carries both a task skill $s$ and a branch-local meta-skill $m=(ψ,σ,α,π,\varepsilon)$ whose five components parameterise the Analyzer, Retriever, Allocator, Proposer, and Evolver agents of the improvement pipeline. Task skills evolve on a fast loop while the meta-skill evolves on a slower one under the same pipeline applied to itself, with no additional model or objective. With all five pipeline agents sharing a single frozen backbone, MetaSkill-Evolve outperforms no-skill, static-skill, and single-level evolution baselines on three agentic benchmarks (OfficeQA, SealQA, ALFWorld), improving held-out test accuracy over the raw backbone by +23.54, +16.09, and +1.92 points respectively.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有LLM智能体自改进方法（如EvoSkill、SkillWeaver等）仅能优化任务技能（**智能体做什么**），但改进过程本身（**如何改进**）是固定、手工编写的，无法随任务动态演化。
- **瓶颈**：固定的改进流程导致搜索引擎能在高质量技能上停滞（高效用但低元生产力），无法调整失败诊断方式、搜索预算分配、跨分支经验复用等策略，最终使自改进陷入瓶颈。
- **核心思路**：将改进过程本身也作为可进化的对象，实现**递归自改进**——即改进操作的自我应用，且无需新模型或新目标函数。
- **整体意义**：提出一种实用的、有界的递归自改进框架，显著提升智能体在长周期、开放式任务上的适应能力，证明了“如何改进”与“改进什么”应当共同进化。

## 2. 方法论：核心思想、关键技术细节
### 2.1 核心思想：双时间尺度进化
- **快循环（Fast Loop）**：每个迭代更新**任务技能**$s$，基于单次失败案例进行诊断、检索、分配、提议、执行。
- **慢循环（Slow Loop）**：每$H$个快循环更新一次**元技能**$m$，基于过去$H$次任务技能迭代的历史表现作为信号，同一条流水线（五个代理）递归作用在元技能文件上。

### 2.2 分支状态与元技能表示
- 每个分支状态 $b = (s, m, h)$，其中：
  - $s$：任务技能（Markdown格式的LLM Agent程序）。
  - $m = (\psi, \sigma, \alpha, \pi, \varepsilon)$：元技能，五个组件分别对应五个代理：
    - $\psi$：分析器，失败诊断与标签生成。
    - $\sigma$：检索器，跨分支经验复用控制。
    - $\alpha$：分配器，自适应子代预算$K \in [1, K_{\max}]$。
    - $\pi$：提议器，将诊断转化为具体编辑提议。
    - $\varepsilon$：进化器，执行编辑并验证。
- 每个$m$组件也是Markdown技能文件，因此可被相同流水线处理。

### 2.3 进化图与前沿选择
- 所有历史分支节点持久化在SQLite有向无环图$G$中，每个节点存储$(s_v, m_v, U_v, \Delta U_v, \phi_v)$及选择计数。
- **前沿评分**（式4）：
  $$v^* = \arg\max_{v \in F} \left[ \eta_1 U_v + \eta_2 \hat{P}_v + \eta_3 N_v \right]$$
  - $U_v$：任务效用（验证集准确率）。
  - $\hat{P}_v$：元生产力估计（子代平均增益 $\overline{\Delta U}$）。
  - $N_v = 1/(1+\text{times\_selected}_v)$：节点冷却因子。
  - 三个项分别对抗：锁死在低效父代、忽视有潜力的中等节点、预算垄断。

### 2.4 快循环流程（算法1）
1. 恢复分支快照$(s_v, m_v)$到磁盘。
2. 在训练批次上评估$s_v$，取最差样例作为诊断目标$f$。
3. **分析器**（$\psi$）：输出标签$\phi$和自由形式分析$a$。
4. **检索器**（$\sigma$）：按标签相似性检索候选节点（先过取3倍，再LLM重排）。
5. **分配器**（$\alpha$）：选择子代预算$K$（停滞时扩大，有效编辑时缩小）。
6. **提议器**（$\pi$）：生成$K$个编辑$\delta$，当$K>1$时加入多样性提示。
7. **进化器**（$\varepsilon$）：将$\delta$写入文件并验证哈希一致性。
8. 验证每个子代$s'_k$在验证集上的增益$\Delta U_k$。
9. 若$t \mod H = 0$，触发慢循环更新$m$。
10. 提交子代节点到图，同步前沿。

### 2.5 慢循环流程（算法2）
- 仅在$t \mod H = 0$时执行（默认$H=2$）。
- 构建**元失败追踪**$f_m$：将过去$H$个子代的标签、诊断、结果及平均增益$\hat{P}$整合为类似快循环轨迹的格式。
- 运行同一条流水线，目标对象切换为元技能文件（五个组件）。
  - **分析器**：识别五个组件中最须改进的组件（回退至轮询）。
  - **全技能改写**：每个子代同时编辑所有五个文件（提议器顺序，进化器并行），保证连贯性。
  - **累积子代**：第$k+1$个子代基于第$k$个子代写入的文件继续改进，而非基于父代。

### 2.6 关键技术亮点
- **无新增模型/训练**：五个代理共享同一冻结的Gemma-4 31B骨干。
- **自我递归**：元技能和任务技能同为Markdown文件，同一流水线可递归处理。
- **前沿选择引入元生产力**：超越纯效用驱动，激励探索有前景但尚未高产的分支。

## 7. 优点
- **概念创新**：首次将智能体改进流程本身作为可进化的元技能，实现有界递归自改进，扩展了自改进智能体的能力边界。
- **实现简洁优雅**：元技能与任务技能格式统一，流水线可递归应用于自身，无需额外模型、训练或损失函数。

## 8. 不足与局限
- **评估广度有限**：仅在三个基准上测试（两个QA、一个具身），缺乏在开放式、真实世界长周期任务（如WebAgent、软件开发）上的验证，结论泛化性存疑。

- **元更新视界固定**：默认$H=2$虽最佳，但依赖人工设定；未尝试自适应视界机制。
- **算力消耗未量化**：缺少GPU型号、运行时间、总推理量等数据，使实际可复现性和效率评估困难。
- **偏差风险**：所有实验使用同一骨干（Gemma-4 31B）和同一组作者编写的技能，可能存在编程工件偏差。未在更多样化的骨干和技能起点上验证。
