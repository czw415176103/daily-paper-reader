## 摘要
大型语言模型智能体日益能够进行规划、使用工具、维持记忆并执行长期任务。这些进展引发了两个相互关联的问题：智能体如何改进其学习和行动的机制，以及这种改进如何增强用户持久的能力，而不仅仅是软件本身？本文提出了一种治理下的多智能体架构，用于递归自我改进的智能体，并引入了个人奇点作为一种有限的人机共同发展目标：帮助用户在选定领域内接近一个不断扩展的、用户定义的能力边界。每个智能体由目标合约、有限范围、经验证的工具注册表、工具级测试、端到端基准测试、所有者控制的自主策略、路由策略、记忆和改进策略定义。超出范围的任务将转移给另一个负责任的智能体或新创建的细分智能体。面向用户的Auto-Index选择交互、混合、自主或计划操作，而不覆盖外部权限。该架构结合了快速规划-执行-验证循环、较慢的证据门控改进循环、外部治理平面、去中心化智能体谱系、所有者导向的智能体铸造厂，以及协调工作、计算成像、过程学习和个人学习智能体的个人奇点操作系统。我们形式化了范围、路由、改进接受、有界目标演化、工具优先执行和人类能力转移，并提供了安全不变量、基准设计和实施路线图。这是一篇立场和系统设计论文，并非证明无限制的递归自我改进或个人奇点已经实现。

## Abstract
Large language model (LLM) agents can increasingly plan, use tools, maintain memory, and execute long-horizon tasks. These advances motivate two linked questions: how can an agent improve the mechanisms by which it learns and acts, and how can that improvement increase the durable capabilities of its user rather than only the software itself? This paper proposes a governed multi-agent architecture for recursively self-improving agents and introduces personal singularity as a bounded human-AI co-development objective: helping a user approach an expanding, user-defined capability frontier across selected domains. Each agent is defined by a goal contract, bounded scope, validated tool registry, tool-level tests, end-to-end benchmarks, an owner-controlled autonomy policy, a routing policy, memory, and an improvement policy. Out-of-scope tasks are transferred to another accountable agent or to a newly created niche agent. A user-facing Auto-Index selects interactive, hybrid, autonomous, or scheduled operation without overriding external permissions. The architecture combines a fast planner-executor-verifier loop, a slower evidence-gated improvement loop, an external governance plane, decentralized agent lineages, an owner-directed agent foundry, and a Personal Singularity OS coordinating working, computational-imaging, process-learning, and personal-learning agents. We formalize scope, routing, improvement acceptance, bounded goal evolution, tool-first execution, and human capability transfer, and provide safety invariants, benchmark design, and an implementation roadmap. This is a position and systems-design paper, not evidence that unrestricted recursive self-improvement or personal singularity has already been achieved.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法

### 2.1 核心思想
- **分离原则**：将任务执行、自我改进、治理权限严格分离。智能体是“不被信任的提议者”，外部系统和所有者控制评价与部署。
- **多智能体专业化**：每个智能体通过明确的合约定义其目标、范围、工具、基准、自主性、路由策略、记忆和改进策略。
- **两速循环**：快速任务循环（规划-执行-验证）处理日常任务；慢速改进循环（证据门控）处理记忆、技能、策略和工具的改进。
- **外部治理平面**：独立于智能体运行，拥有签名策略、权限、审计、隐藏评估和回滚能力，智能体无法修改。
- **个人奇点操作系统**：协调四类初始智能体（工作、计算成像、过程学习、个人学习），以用户为中心，确保能力转移。

### 2.2 关键技术细节

#### 智能体状态表示

#### 改进操作与递归定义
\[
A' = I(A, D, B)

当接受更改改变了 \(I\) 或其有效搜索空间时，过程即为递归自我改进。

#### 任务执行算法（Algorithm 1：Bounded end-to-end task execution）
1. 编译任务合约（目标、约束、预算等）。
2. 初始化持久状态。
3. 循环：检索记忆→规划下一步→向外部治理请求授权→在沙箱中执行→验证→更新状态。
4. 直到任务完成（返回经验证的交付物）或遇到策略边界/预算耗尽。

#### 改进接受条件（Formula 5）
\[
\text{Accept}(A, A') = \mathbb{1}\left[ \begin{array}{c}
\text{Perf}(A'; D_{\text{heldout}}) - \text{Perf}(A; D_{\text{heldout}}) \ge \tau_p,\\
\text{Safe}(A') \ge \tau_s,\\
\text{Risk}(A') - \text{Risk}(A) \le \tau_r,\\
\Delta P \subseteq P_{\text{approved}},\\
\text{provenance complete and rollback available}
\end{array} \right]
\]
- 阈值和测试套件由外部控制，候选智能体无法更改。

#### 范围感知路由（Algorithm 3：Scope-aware assignment and handoff）
- 每个任务经过硬范围门筛选（领域、任务类型、权限、风险等）。
- 通过加权评分（领域匹配0.30、任务类型0.25、输入输出兼容性0.15、工具就绪0.15、历史成功率0.10、所有者偏好0.05）选择最佳候选作为主要代理。
- 若任务超出现有范围，则创建新的细分智能体或报告能力缺口。

#### 人类能力转移（Algorithm 4：Human capability transfer after task completion）
- 从任务轨迹提取可转移知识。
- 根据所有者选择的学习模式（委托、教练、助教、考官）生成学习活动。
- 观察练习或教学反馈，评估独立表现，更新能力图。

#### 工具优先率定义
\[
\text{ToolFirstRate} = \frac{\text{工具适用步骤中由验证工具执行的步骤数}}{\text{所有工具适用步骤数}}
\]

### 2.3 关键架构组件
- **Auto-Index**：面向用户的交互模式选择器（0-5级），控制自主程度而不改变硬权限。内部自主性是向量（规划、读、写、测试、恢复等），用户看到的是预定义策略配置文件。
- **目标栈**：\(G = (G_0, G_1, G_2, G_3, G_4)\)，其中 \(G_0\) 为不可变安全宪法，\(G_1\) 创始使命，\(G_2\) 所有者目标，\(G_3\) 经验衍生改进目标，\(G_4\) 当前操作任务。下层可以缩窄但不能覆盖上层。
- **去中心化谱系和智能体铸造厂**：支持克隆、分叉、从干净模板派生、多亲本重组。子智能体不能继承父级凭证、权限或私密记忆。

## 6. 论文的主要结论与发现

1. **递归自我改进智能体不应是重写自身的单体程序**，而应是一个受治理的搜索过程：智能体提议，外部系统授权和评估，所有者控制目标和采用，每个版本可审计和可回滚。
2. **自主任务执行、记忆、技能学习、源码级修改和元改进是不同的层次**，应逐步添加，风险控制应随层次升高而加强。
3. **个人奇点要求软件增长转化为持久的人类增长**，智能体应同时优化任务质量和用户独立能力。
4. **成功系统需要每个智能体具有显式目标、有限范围、验证工具、独立工具测试、端到端基准、所有者控制的Auto-Index和超出范围工作的路由**。
5. **每个接受的需求应分配给一个负责任的智能体**，它可委托但负责集成和验证。
6. **外部治理平面是实现安全递归自我改进的关键**，包括政策引擎、资源调节器、凭证代理、独立评估器、审计日志和回滚控制器。
