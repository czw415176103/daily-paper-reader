## 摘要
常数优化在符号回归的树形遗传规划中微调候选表达式的数值系数，但其每代成本导致现代GPU加速框架要么省略该步骤，要么将其限制为轻量形式。我们提出了一种GPU常驻的批量Levenberg-Marquardt求解器，通过对结构异构的表达式树种群进行常数优化，每次迭代仅需固定次数的种群级CUDA启动。反向模式自动微分在一次后向扫描中组装每棵树的雅可比矩阵，使得每个迭代的主要成本与每棵树的常数数量无关；双精度交付保护确保返回的常数绝不会劣于其初始值。在早期代数种群上，该求解器在NVIDIA A100上可持续处理高达每秒钟$5.1\times10^{5}$棵树；在GPU饱和的基准测试配置下，其吞吐量约为在64核EPYC 7763上运行的Operon的$9.9\times$，同时达到与fp64参考相当的质量。该求解器以进程内方式集成到EvoGP中，使得端到端搜索能够在$18$个构造问题中的$10$个上恢复控制方程，而原生EvoGP在$0$个问题上成功。我们的代码位于https://github.com/TensorConv/CuSR。

## Abstract
Constant optimization refines the numerical coefficients of candidate expressions in tree-based genetic programming for symbolic regression. But its per-generation cost has led modern GPU-accelerated frameworks to omit it or restrict it to lightweight forms. We present a GPU-resident, batched Levenberg--Marquardt solver that optimizes constants across a structurally heterogeneous population of expression trees using a fixed number of population-wide CUDA launches per iteration. Reverse-mode automatic differentiation assembles the per-tree Jacobian in one backward sweep, making the dominant per-iteration cost independent of the number of constants per tree, and a double-precision delivery guard guarantees that returned constants are never worse than their initial values. On early-generation populations, the solver sustains up to $5.1{\times}10^{5}$ trees per second on an NVIDIA A100; at a GPU-saturated benchmark configuration it delivers roughly $9.9{\times}$ the throughput of Operon running on a 64-core EPYC 7763, while matching fp64-reference quality. Integrated in-process into EvoGP, the solver enables end-to-end search to recover governing equations on $10$ of $18$ constructed problems versus 0 for stock EvoGP. Our code is at https://github.com/TensorConv/CuSR.

## 1. 核心问题与整体含义

**研究动机与背景**
- 符号回归（Symbolic Regression, SR）旨在同时搜索候选表达式的**结构与数值常数**。树型遗传规划（Tree-based Genetic Programming, TGP）通过交叉、变异等算子完成结构搜索，但这些算子很难对连续实数常数做局部精调。
- 即使一棵树结构完全正确，若内部常数不准确，其适应度仍可能很差，导致在进化中被淘汰。为此，常数优化（Constant Optimization, CO）在固定树结构下用数值方法（如 Levenberg–Marquardt, LM）最小化预测误差。
- 但 CO 的逐代计算成本极高。现代 GPU 加速 TGP 框架（如 EvoGP）为追求吞吐率普遍省略 CO，或只使用轻量一阶方法，导致“结构搜索很快、数值精度不足”的断层，尤其难以恢复嵌套在非线性函数内部的“内部常数”（如正弦中的频率、指数中的衰减率）。

**核心问题**
- 如何在 GPU 上为**结构异构的整棵种群**提供高效、高质的二阶常数优化，并将其无缝集成到 GPU 常驻的进化搜索循环中？
- 难点包括：host–device 数据拷贝会抵消 GPU 加速优势；不同树的常数个数、计算量和收敛速度不同，与 GPU“均匀批量执行”模型不兼容；现有 CPU 求解器无法直接移植到 GPU 上运行。

**整体意义**
- 论文首次提出“GPU 常驻、批量二阶常优化”方案，使得结构搜索和常数拟合都保持在 GPU 上执行，弥补了 GPU 符号回归系统缺少高质量 CO 的空白。

## 2. 论文提出的方法

**核心思想**
- 设计了一个 **GPU-resident, batched Levenberg–Marquardt 求解器**：一次调用即可拟合整个种群中所有表达式的常数。
- 异构树通过 **结构体数组（Structure of Arrays）编码**统一表示：每棵树只记录节点偏移、节点数、常数偏移和常数个数，不同形状的树仅是不同的连续数组区间，因此无需填充即可共同参与批量计算。
- 采用**固定数量的种群级 CUDA kernel 启动**完成每个 LM 迭代（总计 8 次），与种群大小和每棵树的常数个数无关。

**关键技术细节**
- **三种雅可比构建方式对比**：
  - 有限差分（FD）：每个常数需扰动并重新走树，代价随常数个数线性增长。
  - 前向模式自动微分（fwd AD）：每条 lane 同时处理 8 个切向，复杂度为 \(O(\lceil K_m/8\rceil)\)。
  - **反向模式自动微分（rev AD）**：先做一次带 tape 的前向求值，再做一次反向扫描，单次后向扫描即可得到整行雅可比，构建代价与每棵树的常数个数 \(K_m\) 无关，是默认模式。
- **LM 迭代流程**：
  1. 批量评估当前损失；
  2. 构建雅可比 \(J_m\)；
  3. 组装正规方程 \(J_m^\top J_m\) 和 \(J_m^\top r_m\)；
  4. 用阻尼 Cholesky 求解更新步；
  5. 试算损失，按接受/拒绝规则更新参数和阻尼系数；
  6. 刷新残差。
- **数值稳定性与质量控制**：LM 热路径使用 fp32 和 `--use_fast_math` 以提高吞吐，但在交付前增加 **fp64 交付保护（double-precision delivery guard）**：用双精度重新计算每棵树在初值和终值处的损失，若终值非有限或比初值更差，则回滚到初始常数，保证“返回常数绝不劣于初值”。
- **EvoGP 集成**：以进程内方式把求解器嵌入 EvoGP 遗传循环，避免子进程启动和 CUDA context 重建；每棵树在适应度评估前统一批量拟合常数。实验表明每 5 代调用一次与每代调用在恢复质量上无显著差异，可大幅摊销成本。

## 6. 主要结论

**直接结论**
- 所提出的批量 LM 求解器在 GPU 上达到了非常高的吞吐：在种群规模 \(M=5.12\times 10^4\)、每树数据点 \(N=10^3\) 时，饱和吞吐量为 **440,000 棵树/秒**（含反向模式 AD 与 Cholesky 求解）；端到端 LM 热路径比 Operon 在 CPU 上的吞吐高出约 **2~3 个数量级**，且质量与 CPU 的 fp64 LM 基线相当。
- 质量上，树级损失大多收敛到与 SciPy fp64 `least_squares` 参考解接近的水平；但论文也坦率指出，与参考相比，fp32 GPU 求解器在解的质量上存在“一个数量级的差距”，且某些树的最终损失甚至高于初值。为此引入 fp64 交付保护机制——该机制虽不提升整体平均解的精度，但能有效避免“比不优化更差”的最坏情形，确保返回解从不劣于初始常数。
- 反向模式 AD 在构建雅可比时不受常数个数影响，成为默认选择；在损失“平坦”或雅可比稀疏时，fwd AD 仍有其用武之地，但 rev AD 在整体吞吐和可扩展性上最优。
- 端到端符号回归中，集成 CO 后的 EvoGP 在 18 个含内部常数的真实方程问题上显著优于原生 EvoGP（McNemar 检验 \(p=2.0\times10^{-3}\)），证明“结构搜索与常数拟合交替进行”的闭环能给系统带来质变；而每 5 代调用一次 CO 与每代调用在恢复率上无显著差异（\(p=0.73\)），说明该方法可以被低频调度，进而将性能开销摊销到可接受范围。

**条件性结论与局限**
- 上述吞吐优势依赖于 GPU 达到“饱和”规模（足够大的种群与数据点）方能体现——单棵树的 LM 求解在 GPU 上远慢于 CPU，但在批量维度上取得压倒性优势；若符号回归任务本身种群较小，则本方法无明显收益。
- 论文并不主张对所有问题都能达到与 fp64 参考完全一致的精度；其定位是“高效、可回滚的高质量常数拟合”，用质量下限保证换取速度上限。
- 仅在单张 A100 和 EvoGP 框架上验证；通用性（其他 GPU 架构、其他 SR 系统）与大规模生产环境的稳定性仍有待进一步验证。

## 7. 启示与反思

**对符号回归领域的启示**
- 本研究清晰地定位了 GPU 符号回归的瓶颈转移：当结构搜索被高度并行化后，常数拟合成为新的“短板”；论文证明了这一短板可以通过“为 GPU 原生设计”的二阶优化器弥补，而不是简单移植 CPU 算法。
- 为“结构与常数联合搜索”提供了一个工程范本：非均匀树通过 SoA 布局统一、宿主端避免拷贝、按需调用 CO 以摊销成本等方法均可被后续框架直接采纳。

**方法论启示**
- 与许多“追求极致精度”的数值优化论文不同，本工作明确采用“fp32 为主 + fp64 保险”的务实策略：不追求每次迭代都精确，而保证最终交付不劣于初值。这种思路在深度学习与科学计算交叉的场景中具有广泛参考价值。
- 大批量 LM Cholesky 求解的 kernel 设计（8 次固定 kernel 启动、无分支、无填充）是 GPU 数值优化的良好案例，展示了“把算法结构对齐到机器模型”的重要性。

**可复现性反思**
- 论文详细报告了硬件锁频、ECC、软件版本、随机种子与输入生成方式，并给出可复现的构造性基准（由真实 EvoGP 快照校准的树分布），对复现工作较为友好；但未公布功耗和总算力开销，也未公开所有实验配置下的完整延迟数值，为精确复现留下了空白。
