## 摘要
父代选择显著影响遗传编程（GP）在符号回归中的探索、开发与复杂度控制。目前尚不清楚大型语言模型（LLMs）是否能在零样本设置下，无需迭代元进化即可综合出有效的算子。此处零样本意味着模型仅接收任务描述，没有参考算子或迭代反馈。在本研究中，我们在标准GP框架下对八个LLM进行父代选择算子的零样本综合基准测试。每个模型接收相同的自然语言提示以生成父代选择算子，随后在标准GP框架中仅替换父代选择算子，而所有其他组件和进化搜索预算保持不变。对于每个LLM，在十二个OpenML回归基准上评估十个独立的零样本算子，并与自动lexicase和锦标赛选择基线进行比较。Claude Sonnet~4.6和Gemini~3.1 Pro在训练集和留出测试$R^2$上均表现出持续强劲的性能。我们基准测试中最强的算子——一种Kimi~K2.5零样本综合——在搜索有效性上超过了自动lexicase和锦标赛基线。这些结果表明，零样本LLM综合是生成有竞争力的GP选择算子的一种可行方法。分析显示，许多生成的算子使用语义来指导选择，这表明LLM可以仅从任务描述中产生非平凡的搜索启发式算法。我们还考察了公共LLM排行榜排名与GP性能之间的关系。广泛使用的基准，如Humanity's Last Exam和SWE-bench Verified，与训练$R^2$强烈相关，而它们与留出测试$R^2$的关系较弱且不太明确。

## Abstract
Parent selection significantly affects exploration, exploitation, and complexity control in genetic programming (GP) for symbolic regression. It is unclear whether large language models (LLMs) can synthesize effective operators in a zero-shot setting without iterative meta-evolution. Here, zero-shot means that the model receives only the task description, with no reference operators or iterative feedback. In this work, we benchmark zero-shot synthesis of parent-selection operators across eight LLMs within a standard GP framework for symbolic regression. Each model receives the same natural-language prompt to generate a parent-selection operator, which is then evaluated in a standard GP framework with only the parent-selection operator replaced, while all other components and the evolutionary-search budget are held constant. For each LLM, ten independent zero-shot operators are evaluated on twelve OpenML regression benchmarks and compared against automatic lexicase and tournament selection baselines. Claude Sonnet~4.6 and Gemini~3.1 Pro stand out for consistently strong performance on both training and held-out test $R^2$. The strongest operator in our benchmark---a Kimi~K2.5 zero-shot synthesis---surpasses the automatic lexicase and tournament baselines in search effectiveness. These results suggest that zero-shot LLM synthesis is a viable approach to generating competitive GP selection operators. Analysis shows that many generated operators use semantics to guide selection, suggesting that LLMs can produce non-trivial search heuristics from the task description alone. We also examine the relationship between public LLM leaderboard rankings and GP performance. Widely used benchmarks, such as Humanity's Last Exam and SWE-bench Verified, strongly correlate with training $R^2$, while their relationship to held-out test $R^2$ is weaker and less clear.

- **研究动机**：在遗传编程（GP）中，父代选择直接影响探索/开发平衡、多样性维持和复杂度控制，是决定符号回归搜索性能的关键环节。尽管锦标赛选择和 lexicase 选择等人工设计算子已被广泛研究，但如何自动设计更优的选择算子仍是开放问题。
- **背景**：大语言模型（LLM）能够从自然语言生成可执行代码，为“自动算法设计”提供了新路径。以往工作（如 FunSearch、LLaMEA、Evolution of Heuristics 等）大多依赖多轮迭代或外部进化循环，难以分离 LLM 单次调用的内在零样本能力。

## 2. 方法论

### 2.1 核心思想

- 构建一个标准 GP 符号回归框架，**仅替换父代选择算子**，其余组件（初始化、交叉/变异、适应度评估、精英保留）和搜索预算全部固定，从而将性能差异归因于选择算子的行为。
- 每个 LLM 接收完全相同的自然语言 prompt，零样本生成一个选择算子。算子被嵌入 GP 框架后，在多个回归数据集上评估。

### 2.2 关键技术细节

- **GP 框架设置**：种群大小 200，100 代；交叉率 0.9，变异率 0.1；函数集包含算术、对数、平方根、绝对值、三角函数等；利用线性缩放和 R² 作为适应度；采用 ramped half-and-half 初始化；top-1 精英策略。
- **零样本 prompt**：要求 LLM 实现具有固定签名的函数 `def custom_selection(population, k=100, status={})`，可利用个体信息（如逐样本误差向量、预测值、残差、节点数）和进化阶段信息（`status["evolutionary_stage"]`）。要求优先使用 NumPy 向量化、不超过 30 行代码。
- **算子验证**：生成的代码先经过语法检查和小型功能测试（确认返回正确数量的个体），不经过符号回归评估；失败则重新生成，直到每个 LLM 获得 10 个有效算子。

### 2.3 算法流程示例

- **Kimi K2.5 的代表算子**（训练性能最优）：
  - 构造逐案例误差矩阵，并计算每案例方差。
  - 设计“课程式权重”：随进化阶段 t 增加，给高方差案例更高权重，引导搜索关注尚未解决的区域。
  - 加权误差 + 基于残差的 novelty 项 + 树大小简约项组成选择分数。
  - 锦标赛规模随 t 增大（从 2 逐渐升至 8），从而在后期增强选择压力。
  - 复杂度为 O(nm)，而非全对全距离的 O(n²m)，说明 LLM 能设计高效算法。

- **GPT-5.4 的代表算子**（测试性能最优）：
  - 利用预测矩阵构建相似性矩阵，识别表型相似的冗余个体。
  - 将适应度、多样性、树大小/深度按阶段变化权重组合。
  - 引入软最大（Boltzmann）选择，并对高相似邻域的个体降权，同时保留小规模精英块。

- **仅覆盖 GP 符号回归任务**：结论能否迁移到其他 GP 领域（如程序合成、聚类、图像分类）或非 GP 优化算法设计仍属未知；符号回归特有的个体语义结构（逐样本误差向量）可能恰好利于 LLM 生成启发式算子，其他领域未必如此。

## 9. 总结与启示

- **总体判断**：该论文以“零样本 LLM 合成 GP 选择算子”为切入点，系统性地回答了 LLM 能否在无反馈条件下设计出可竞争的人工选择算子这一问题。答案是“能，但有条件地能”：少数 LLM 的部分生成算子在训练集上可超越经典基线，但在测试集上仍存在稳定差距，说明 LLM 具备较强的启发式构造能力，但在泛化优化上还不足。
- **对自动算法设计领域的启示**：零样本合成可作为低成本的“第一代算子候选生成器”使用，再辅以后续的评估、筛选或近端迭代优化，有望逼近甚至超过人工设计水平；此外，该范式天然支持流水线化并行——一次调用 LLM 生成大量候选算子，再靠 GP 评估筛选，计算预算与模型成本均可控。
- **对 LLM 能力评测的启示**：论文表明公共排行榜分数能较好预测 LLM 在“训练阶段搜索优化”方面的能力，但无法预测泛化能力；这提示社区不能仅依赖单一基准分数评估算法设计能力，而应区分“拟合性创造力”和“泛化性设计力”。
- **方法论上的可复制性**：该工作采用“固定框架 + 单一组件替换”的受控评估范式，设计简洁、可复制性强，为未来将 LLM 引入更多 GP 组件（如初始化、交叉变异、适应度函数）的设计提供了清晰的参考框架。
- **改进空间**：未来可在以下方向进一步拓展：（1）引入少量地面真值反馈，观察少量迭代是否显著提升测试泛化；（2）在更多 GP 任务与更多样化的数据集上重复实验；（3）设计多 prompt 或多语言描述变体，检测提示敏感性；（4）将 LLM 生成算子与元学习结合，实现在线自适应选择。
