## 摘要
LLM训练正从手动设计和标注转向交互驱动的自我进化。然而，现有的自我进化方法在任务多样性与验证可靠性之间面临根本性困境：受限于环境的方法能够获得精确反馈，但将学习局限在狭窄领域；而开放式自我生成虽然拓宽了任务空间，但缺乏可靠验证，使得误导性奖励污染训练循环。我们识别出智能体技能作为调和这一紧张关系的强大中间地带：每个技能确保在特定场景中实现深入、可验证的执行，而跨技能的动态路由则保持了开放式的任务多样性。基于这一洞察，我们引入了技能自博弈（Skill-SP），一种共同进化框架，包含提议者、求解者和动态技能控制器。通过强化学习循环的编排，这些组件在持续的自博弈循环中共同进化：提议者基于动态采样的技能生成具有挑战性的任务；求解者探索候选解决方案以突破其能力边界；技能控制器收集执行反馈以更新和扩展技能库。这种交互式共同进化有效弥合了结构化验证与开放式探索之间的鸿沟。在工具使用和推理基准上的实证评估表明，Skill-SP作为稳健的进化引擎，持续推动强大基座模型的性能上限，同时催化初始偏差模型的显著逆转。我们的代码可在 https://github.com/Qwen-Applications/skill-self-play 获取。

## Abstract
LLM training is shifting from manual design and annotation to interaction-driven self-evolution. However, existing self-evolutionary methods face a fundamental dilemma between task diversity and verification reliability: environment-bound methods obtain precise feedback but confine learning to narrow domains, while open-ended self-generation broadens the task space but lacks reliable verification, allowing misleading rewards to pollute the training loop. We identify agent skills as a powerful middle ground to reconcile this tension: each skill ensures deep, verifiable execution in a specific scenario, while dynamic routing across skills maintains open-ended task variety. Leveraging this insight, we introduce Skill Self-Play (Skill-SP), a co-evolutionary framework comprising a proposer, a solver, and a dynamic skill controller. Orchestrated via a reinforcement learning loop, these components co-evolve in a continuous self-play loop: the proposer generates challenging tasks conditioned on dynamically sampled skills; the solver explores candidate solutions to push its capability boundaries; and the skill controller collects execution feedback to update and expand the skill library. This interactive co-evolution effectively bridges the gap between structured verification and open-ended exploration. Empirical evaluations on tool-use and reasoning benchmarks demonstrate that Skill-SP, serving as a robust evolution engine, consistently pushes the performance ceiling of competent backbones while catalyzing striking turnarounds for initially misaligned models. Our code is available at https://github.com/Qwen-Applications/skill-self-play.

## 2. 方法论

### 2.1 核心思想
- **Skill Self-Play (Skill-SP)**：一个共同进化框架，通过强化学习自博弈循环，实现三个组件的协同进化：**提议者（Proposer）**、**求解者（Solver）** 和**动态技能控制器（Controller）**。
- 每个训练迭代中，提议者基于从进化技能库中动态采样的技能生成任务；求解者学习求解这些任务；控制器分析执行轨迹以管理技能库（精炼、修剪、归纳新技能）。

### 2.2 关键技术细节
- **技能表示**：每个技能 $s$ 是一个六元组 $\langle m, r, h, e, v, \sigma \rangle$，其中 $m$ 为路由元数据，$r$ 为生成规则，$h$ 为提示/约束，$e$ 为示例，$v$ 为可执行验证器，$\sigma$ 为使用统计。
- **双流生成**：
  - **技能引导流**：$(\bm{x}, \bm{c}) \sim \pi_{\text{propose}}(\cdot|s)$：注入结构化先验。
  - **开放探索流**：$(\bm{x}, \bm{c}) \sim \pi_{\text{propose}}(\cdot|\emptyset)$：无技能约束，探索新任务空间。
- **有效性验证**：技能流任务的合法性由三项组成：模式合规、合约有效、探测一致性（从当前求解器 $K$ 次rollout中多数答案匹配参考）。探索流任务仅需全局模式合规和探测一致性。
- **门控课程奖励**：
  $$R_{\text{propose}}(\bm{x},\bm{c};\pi_{\text{solve}}) = \mathbb{1}_{\{\text{有效}\}} \cdot \left(1 - 2\left|v_{\text{solve}}(\bm{x},\bm{c};\pi_{\text{solve}}) - 0.5\right|\right)$$
  其中 $v_{\text{solve}}$ 是求解器在生成任务上的预期成功率。
- **课程构建**：从双流有效任务中选取前沿奖励最高的 $M$ 个任务，按比例 $\alpha$ 混合。
- **策略优化**：提议者和求解者均使用 **Group Relative Policy Optimization (GRPO)** 更新。
- **技能库进化**（每轮迭代）：
  - **精炼**：从无效尝试和成功轨迹中更新技能内容。
  - **修剪**：移除产出平庸任务的饱和技能（前沿奖励 < 阈值）。
  - **归纳**：从探索流中提取前沿奖励高的候选任务，由技能控制器（初始基座模型）抽象为新技能包，经完整性和新颖性过滤后加入库。
- **算法流程**（Algorithm 1）：
  1. 采样技能，生成候选人（双流）。
  2. 验证候选人，计算 $R_{\text{propose}}$，保留有效候选。
  3. 按前沿奖励排序构建混合课程 $D^{(t)}$。
  4. 更新提议者和求解者策略。
  5. 进化技能库（精炼、修剪、归纳）。

## 8. 不足与局限
- **初始能力阈值**：对于极端复杂的任务（如ZebraLogic XL规模），弱模型因无法引导有效学习信号，Skill-SP提升有限。论文也承认发现全新任务模式需要基座模型具备最低基础能力。
- **固定启发式参数**：论文使用固定的混合比$\alpha$、难度边界、修剪阈值等，这些可能需要在新的任务族上进行经验调参。作者提出未来将学习动态课程调度器来替代。
- **技能归纳能力限制**：技能控制器使用初始基座模型（而不是更强的模型）来抽象新技能，可能限制复杂模式的学习。尽管当前情况下已有效，但更强的归纳器可能进一步提升性能。
- **实验域有限**：仅在工具调用和逻辑推理两个领域验证，未涉及其他智能体任务（如网页交互、代码生成、多跳问答）。技能作为中间地带的泛化性需更多验证。
- **评估基准局限性**：ZebraLogic为确定性推理任务，技能验证器是显式检查器；工具调用验证依赖精确匹配。对于需要更隐式或软性验证的任务（如开放域对话），该方法可能需调整。
- **共进化计算开销**：虽然整体一天多，但求解者课程构建占57%的运行时，主要花在生成和探测候选人上。对更大模型或更多迭代，开销可能增长。
- **未分析模型大小影响**：5个模型参数范围3B-14B，但未系统分析Skill-SP不同规模下的收益规律（如小模型提升更大？中等模型稳定？）。
- **技能库初始构建依赖**：初始技能库由LLM提出并过滤，虽共享所有模型，但可能引入偏见。论文的“冻结技能”消融显示大部分增益来自在线进化而非初始库，但初始库设计仍需人工或LLM干预。
