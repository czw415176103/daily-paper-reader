## 摘要
大型语言模型（LLM）智能体通过强化学习（RL）进行复杂决策任务的训练。然而，大多数经过RL训练的智能体仍然是 episodic 的，无法跨情节积累可复用的知识。近期基于技能的方法（如 SkillRL）试图通过从原始轨迹中提取技能来解决这一问题，但将技能库视为仅追加的存储库，未验证存储的技能是否仍然有效。在本文中，我们提出了 SkillForge，一个持续技能演化的框架，使得技能能够通过环境交互进行验证和精炼。通过在智能体交互过程中明确技能的使用，RL 可以直接优化环境动作和技能调用决策。SkillForge 进一步引入了基于证据的技能验证和多路径技能归纳，使技能库在持续增长的同时保持其质量。在 ALFWorld、WebShop 和 AppWorld 上的大量实验表明，SkillForge 始终优于 SkillRL，证明了持续验证的技能在训练更强大的 LLM 智能体方面的有效性。

## Abstract
Large language model (LLM) agents are trained with reinforcement learning (RL) for complex decision-making tasks. However, most RL-trained agents remain episodic and cannot accumulate reusable knowledge across episodes. Recent skill-based approaches, such as SkillRL, attempt to address this issue by extracting skills from raw trajectories, but treat the skill bank as an append-only repository without verifying whether stored skills remain effective. In this paper, we propose SkillForge, a framework for continuous skill evolution that enables skills to be verified and refined through environment interaction. By making skill usage explicit during agent interaction, RL can directly optimize both environment actions and skill invocation decisions. SkillForge further introduces evidence-based skill verification and multi-pathway skill induction, allowing the skill bank to continuously grow while maintaining its quality. Extensive experiments on ALFWorld, WebShop, and AppWorld show that SkillForge consistently outperforms SkillRL, demonstrating the effectiveness of continuously verified skills in training stronger LLM agents.

## 2. 方法论

### 2.1 核心思想

SkillForge 的核心是**让技能的使用显式化，从而使技能可被验证和优化**。具体而言：

- 智能体不再被动接收全部技能描述，而是收到一个**紧凑的技能目录**（仅含技能名称和一行用途说明）；
- 智能体通过结构化 `<skill_call>NAME</skill_call>` 标签**按需显式调用**技能，每次调用成为轨迹中的离散事件；
- 由于技能调用标记属于生成的 token 序列，RL 可以直接同时优化环境动作和技能调用决策；
- 每次调用与回合结果关联，形成可追踪的统计证据，驱动技能的验证与修复。

### 2.2 关键技术细节

**(1) 技能表示（Skill Schema）**

每个技能是一个结构化知识单元，包含：

- **title**：可调用的唯一标识符；
- **intent**：技能用途的一句话描述（在目录中展示）；
- **principle**：核心决策策略（调用后才返回）；
- **applicability**：适用条件/触发条件；
- **category**：通用技能（general）或任务特定技能（task-specific）；
- **status**：active / under-review / deprecated。

**(2) 技能库初始化**

使用初始指令微调模型在目标环境 rollout，由教师 LLM 将成功轨迹蒸馏为策略性技能、将失败轨迹综合为纠正性教训，形成两级层次结构（通用技能 + 任务特定技能）。

**(3) 检索与目录注入**

每回合开始，基于嵌入向量的语义相似度从技能库中检索 top-K 技能，格式化为紧凑目录（仅含名称和一行触发描述）注入系统提示词：

$$S_{ret} = \text{Top-K}_{s \in B} \cos(e_d, e_s)$$

这种设计使提示词长度与技能库大小无关，完整技能内容仅在显式调用时返回。

**(4) 显式技能调用与策略优化**

- 智能体每步输出为环境动作 + 可选的技能调用：$a_t = (a_t^{env}, c_t)$，其中 $c_t \in \{\emptyset\} \cup S_{ret}$；
- 调用技能后，下一个观测包含环境反馈和技能的完整内容；
- 使用 **GRPO** 更新策略，同目标同时优化动作和技能调用决策：

$$J(\theta) = \mathbb{E}\left[\frac{1}{G}\sum_{i=1}^{G} \min\left(\rho_i \hat{A}_i, \text{clip}(\rho_i, 1-\epsilon, 1+\epsilon)\hat{A}_i\right) - \beta D_{KL}(\pi_\theta \| \pi_{ref})\right]$$

- 每个轨迹由 LLM 抽象为结构化摘要，按成功/失败分区存储。

**(5) 多路径技能归纳（Multi-Pathway Skill Induction）**

每 $I=5$ 步，教师 LLM 依据轨迹抽象，从三条路径合成新技能：

- **extraction**（提取）：从成功轨迹中提取可推广策略（仅成功可用时）；
- **refinement**（精炼）：从失败轨迹中识别重复失败模式，制定纠正策略（仅失败可用时）；
- **contrastive**（对比分析）：配对成功与失败，识别决定性行为差异（成功和失败都存在时）。

新技能经**词汇匹配 + 语义相似度**双重去重后加入技能库，保证库的紧凑性。

**(6) 基于证据的技能验证（Evidence-Based Skill Verification）**

每个技能维护统计信息：

- **EMA 成功率**：$\hat{p}_s \leftarrow \alpha \cdot r + (1-\alpha) \cdot \hat{p}_s$，$\alpha = 0.1$；
- **总使用次数** $n_s$；
- **欠佳分数（confidence score）**：$\text{conf}(s) = (1 - \hat{p}_s) \cdot (1 - 0.5^{n_s/h})$，$h = 20$ 为使用半衰期。

欠佳分数高的技能被标记并送入 LLM reflexion，由教师模型依据使用情境输出 **keep（保留）** 或 **revise（修订）** 的裁决；修订时重写 principle 和 applicable conditions。该机制防止知识衰退，维持技能库整体可靠性。

**(7) 训练流程（Algorithm 1）**

每个训练步：检索目录 → 显式技能调用 rollout → GRPO 更新 → 轨迹抽象与分区 → 更新技能统计 → 每 I 步执行技能库维护（归纳 + 去重 + 验证 + 反思）。

**8. 不足与局限（续）**

2. **技能库可能持续膨胀**：尽管有去重和验证机制，长期训练中技能数量仍然存在继续增长的压力。论文实验仅观察了约 90 条技能的上限，但更长期或更复杂环境下技能库能否保持受控增长尚未验证；
3. **依赖检索质量**：技能目录的检索基于嵌入向量的语义相似度，若嵌入模型无法在语义层面区分细微的技能差异，可能将不相关技能注入目录，干扰智能体决策；
4. **显式调用依赖指令遵循能力**：`<skill_call>` 标签机制建立在模型能正确输出结构化 token 的前提下，较弱的策略模型可能不会稳定遵循该格式，导致技能调用信号稀疏或噪声大；
5. **基准范围有限**：ALFWorld、WebShop、AppWorld 均为具有明确目标与可自动判定成败的模拟环境，未涉及开放式对话、代码生成、多智能体协作等更复杂的长期任务场景，结论的外部效度有待验证。

### 论文未明确声明、但读者可注意到的局限

- **消融实验覆盖不充分**：三大组件的消融仅在 Qwen3-4B 一个模型上进行，未交叉验证不同模型规模下各组件的边际贡献，无法排除组件收益与模型规模的交互效应；
- **基线缺失**：未与更多技能学习框架（如 Voyager、Omni 等）进行直接对比；AppWorld 上闭源模型 GPT-4o、Gemini 的结果显示为 "--"，削弱了与最强基线的对照力度；
- **教师裁决的可信度未量化**：LLM Reflexion 的 keep/revise 决策本身可能出错，论文未评估教师误判率对技能库质量的二次影响；
- **跨模型迁移实验方向单一**：仅验证了 Qwen3-4B → Qwen3-30B-A3B 的单向迁移，未测试跨系列、跨骨干（如 7B → 30B）及跨环境迁移，技能的可迁移性边界仍未界定。

## 9. 未来研究方向

基于论文的机制设计与遗留问题，可推断出以下几点有前景的后续工作方向：

1. **弱化教师依赖**：探索用小型验证器、规则化 reward 或自监督信号替代教师 LLM 的归纳与裁决，降低对 Qwen3-Max 这类强模型的依赖；
2. **技能库生命周期管理**：引入技能"遗忘"与"归档"机制，借鉴认知科学中的记忆巩固与睡眠重放思想，让技能库在长期持续学习中保持精炼；
3. **跨环境技能迁移**：验证在 ALFWorld 中习得的技能能否迁移至 WebShop 或 AppWorld，以支撑"通用技能"的抽象层级设计；
4. **扩展到开放式任务**：将显式技能调用机制应用到时序更长、成功信号更模糊的真实场景（如网页导航、代码调试、具身操作），检验其在稀疏奖励下的有效性。

## 10. 综合评价

SkillForge 是一篇问题意识清晰、机制设计闭环、实验支撑较完整的高质量工作。它准确识别出既有技能学习框架"只增不改"的三大缺陷，并逐一对症下药——显式调用解决可观测性、轨迹关联解决可归因性、EMA 统计 + LLM Reflexion 解决质量可控性。其最有价值的贡献在于**将技能库从静态资源库转变为可进化、可验证的知识系统**，为 LLM 智能体的跨回合持续学习提供了一个可复现的工程范式。

实验设计方面的亮点在于：跨模型迁移实验直接证明技能存储的是可迁移知识；训练时长对比打破了"额外机制必然增加开销"的直觉；教师敏感性分析则隔离了框架收益与教师模型能力。

不足主要集中于对教师 LLM 与嵌入模型的依赖、基准环境多样性有限、以及消融实验覆盖范围较窄。总体而言，SkillForge 在方法创新性、实验系统性和结果说服力上都属上乘，对智能体持续学习、技能库管理与 RL 训练结合等方向具有明确的参考价值。
