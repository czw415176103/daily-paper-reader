## 摘要
技能库通过使大语言模型（LLM）代理能够重用程序性知识，提高了代理强化学习（RL）的样本效率。然而，现有范式存在结构性缺陷：它们要么将技能演化与策略优化解耦，要么将元技能实例化为固定工作流。这两种方式都将技能视为待管理的被动对象，限制了技能的灵活演化及其与推理代理的共同适应。为解决这些局限性，我们提出了CoSkill，一个统一的多代理强化学习框架，它将静态的元技能工作流重塑为可学习的元技能代理，并在分层技能库上将其与推理代理联合训练。通过将推理代理和元技能代理建模为共享同一骨干网络、相互协作的团队，CoSkill实现了端到端的共同适应：推理代理根据检索到的任务技能及其子集中选出的步骤技能来调节其动作，而其任务表现则引导元技能代理改进这些步骤技能。在ALFWorld和WebShop上的实验表明，CoSkill显著优于先前的基于技能的基线和强化学习基线，分别实现了98.4%和90.6%的成功率（分别提高3.5和6.2个百分点）。如图1所示，CoSkill在早期样本效率、渐近性能和挂钟效率方面均表现出色。我们的代码可在 https://github.com/jinyuan-cookie/CoSkill 获取。

## Abstract
Skill libraries improve the sample efficiency of agentic reinforcement learning (RL) by enabling large language model (LLM) agents to reuse procedural knowledge. Yet existing paradigms exhibit structural shortcomings: they either decouple skill evolution from policy optimization or instantiate meta-skills as fixed workflows. Both treat skills as passive objects to be managed, limiting the flexible evolution of skills and their co-adaptation with the reasoning agent. To address the limitations, we propose CoSkill, a unified multi-agent RL framework that recasts the static meta-skill workflow as a learnable Meta-Skill Agent and jointly trains it with a Reasoning Agent over a hierarchical skill library. By modeling the Reasoning and Meta-Skill Agents as a cooperative team sharing a single backbone, CoSkill enables end-to-end co-adaptation: the Reasoning Agent conditions its actions on a retrieved task skill and step skills selected from its child set, while its task performance guides the Meta-Skill Agent in refining those step skills. Experiments on ALFWorld and WebShop show that CoSkill substantially outperforms prior skill-based and RL baselines, achieving success rates of 98.4% and 90.6%, respectively (+3.5 and +6.2 pp). As shown in Figure 1, CoSkill achieves superior early-stage sample efficiency, asymptotic performance, and wall-clock efficiency. Our code is available at https://github.com/jinyuan-cookie/CoSkill.

## 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题：**

- 在智能体强化学习（Agentic RL）中，技能库（Skill Library）虽然能通过让 LLM 代理复用程序性知识来提升样本效率，但现有技能演化范式存在结构性缺陷，阻碍了技能与推理代理之间的协同进化。
- 现有三大范式均将技能视为**被动管理对象**，而非**主动参与优化的决策主体**：
  1. **外部编排式技能演化**（Externally Orchestrated Skill Evolution）：技能生成/更新由外部 LLM 或人工规则完成，完全脱离策略学习目标，导致技能库可能随策略演化而过时、冗余或失配。
  2. **RL 优化的技能库管理**（RL-Optimized Skill-Library Management）：虽将库生命周期纳入 RL 循环，但粒度过粗，技能被当作"原子"对象，内部程序未获优化，导致"有用但不完美"的技能可能被弃用而非被精炼。
  3. **元技能驱动的技能优化**（Meta-Skill-Driven Skill Optimization）：虽能优化技能内容，但依赖预定义元技能程序（固定 workflow），且冻结推理代理，无法与演化中的策略共同适应。
- 核心挑战：**学习能够与推理策略共同演化的元技能**，实现端到端的技能-策略协同进化。

**整体含义：**
CoSkill 提出一个统一的多智能体 RL 框架，将元技能从"固定工作流"重新定义为"可学习的元技能智能体（Meta-Skill Agent）"，并与推理智能体（Reasoning Agent）联合训练，从而同时解决"技能-策略解耦"和"元技能固定化"两个问题，在分层技能库上实现细粒度的技能-策略共同进化。该方法在 ALFWorld 和 WebShop 上取得最优性能，验证了技能演化应作为可学习过程与推理共同优化这一核心观点。

## 2. 论文提出的方法论

**核心思想：**
- 提出"分层技能库 + 共享骨干双角色协作 + 端到端联合优化"的统一框架。
- 关键设计洞见：**将元技能定义为 RL 可训练的智能体**（而非固定工作流），使其更新策略能与推理策略共同适应；通过角色共享同一 LLM 骨干，实现参数高效的协同训练。

**关键技术细节：**

### 2.1 分层技能库
- 构建任务索引的**分层技能库**：每个 Task Bundle 包含一个全局任务技能（task skill）\(s^{task}_k\) 及其子步骤技能集合 \(S^{step}_k\)。
- **两级检索**：先全局检索任务技能（基于任务指令与 key 的向量相似度），再从该任务的子集中检索步骤技能（基于当前观测与源观测的相似度）：
  \[
  k^* = \arg\max_k \text{sim}(f(x), f(q_k)), \quad j_t^* = \arg\max_{j \in S^{step}_{k^*}} \text{sim}(f(o_t), f(o_{k^*,j}))
  \]
- 任务技能提供稳定的任务级全局指导，步骤技能随观测提供自适应的局部决策。
- 技能库在 RL 之前通过离线轨迹进行初始化构建（含轨迹收集、分层归纳、grounding 校验与插入）。

### 2.2 共享参数的多代理半马尔可夫决策过程（MSMDP）
- 将推理代理与元技能代理的交互建模为**部分可观测、共享参数的多智能体半马尔可夫决策过程**。
- **角色特定观测**：
  - 推理代理观测 \(u^R_t \in \Omega^R\)：当前任务状态、交互历史、检索到的任务技能和步骤技能；
  - 元技能代理观测 \(u^S_t \in \Omega^S\)：推理上下文投影（当前状态、活动步骤技能、历史）∪ 推理动作 ∪ 环境反馈（奖励、辅助反馈、下一观测）。
- **异构动作空间**：
  - 共享策略 \(π_\theta\) 和 token 空间，但通过不同角色 prompt 引导：
    - 推理代理：环境动作 \(A^R\);
    - 元技能代理：结构化技能编辑 \(A^S = \{INSERT, UPDATE, DELETE, KEEP\}\)。
- **顺序交互与延迟更新**：基线轨迹（\(m=0\)）中所有编辑建议被暂存，不实时修改技能库；尝试结束后构建私有编辑后的 bundle \(\tilde{B}_i\)，经验证后才可能提升到持久库。

### 2.3 编辑后技能验证奖励（Post-Edit Skill Verification Reward）
- 编辑序列的价值须通过**下游任务执行**而非触发编辑的即时转移来评估。
- 基线尝试得到返回 \(R^{(0)}_i\)，随后重置同一任务并使用私有编辑 bundle 执行 \(M\) 次验证尝试，得到 \(R^{(1)}_i, \dots, R^{(M)}_i\)。
- 编辑序列的奖励为**平均编辑后改进**：
  \[
  \Delta^{skill}_i = \frac{1}{M}\sum_{m=1}^{M} R^{(m)}_i - R^{(0)}_i
  \]
- 基线相减控制任务难度；多轮验证降低方差。验证轨迹仅供推理学习，其奖励不回溯分配至基线动作。
- **库增长控制**：只有有效且非平凡的编辑且验证提升成功的 bundle 才成为提升候选；按任务组排序后每组只保留 top-\(K_{prom}\) 的新版本，同时保留原版。

### 2.4 基于 GiGPO 的联合优化
- 采用 **Group-in-Group Policy Optimization (GiGPO)** 作为角色级信用分配框架：
  \[
  A^\rho_{i,t} = A^\rho_{E,i} + \omega^\rho A^\rho_{S,i,t}
  \]
  - Episode 级相对优势：推理轨迹按同任务各 rollout 的回合收益比较；编辑轨迹按同任务、同基准技能的各编辑序列的 \(\Delta^{skill}\) 比较；
  - Step 级相对优势：推理动作以 \((x, o_t)\) 为锚点分组，技能编辑以 \((x, o_t, Z^{step}_t)\) 为锚点分组。
  - 两种角色的统计量分别归一化，避免奖励尺度泄漏。
- 联合更新共享 actor：
  \[
  L(\theta) = L^R_{GiGPO}(\theta) + L^S_{GiGPO}(\theta)
  \]
- 同一优化步骤内推理与技能编辑协同适应。

## 6. 论文的主要结论与发现

- **主结果全面最优**：CoSkill 在 ALFWorld 平均成功率 98.4%（+3.5 pp），在 WebShop 得分 95.9（+4.3 pp）、成功率 90.6%（+6.2 pp），均超过最强基线。
- **联合训练优于外部编辑器规模**：胜过用 Gemini-3-Flash/O3 做外部编辑器的 D2Skill 变体，证明"技能精修与目标环境奖励对齐"比单纯增大编辑器模型规模更关键。
- **细粒度步骤技能优化优于粗粒度库管理**：相比 Skill1，在 ALFWorld 提升 +4.7 pp，在 WebShop 成功率提升 +15.6 pp，验证了层级式的、步骤级程序修订的优越性。
- **消融结论**：
  - 无 Meta-Skill RL 时早停样本效率显著下降（Step 20：−12.50 pp，最终 −3.12 pp）；
  - 扁平化技能库破坏稳定性（最终 −1.56 pp）；
  - 稀疏交替更新（间隔 10/20）引起最大后期退化（Step 120 时 −17.19/−14.06 pp），证明频繁联合更新至关重要。
- **动力学分析结论**：
  - RL 使元技能代理从高熵随机编辑收敛为稳定的 97–99% UPDATE 定向修正，破坏性 DELETE 几乎消失；
  - RL 削减 47.6% 的冗余 bundle 晋升（387 vs 739），同时性能更好；
  - RL 保持了近 100% 的步骤技能检索命中率，并将空步骤 bundle 率从 12.4% 降至 0.2%。
- **总体立场**：技能演化应作为与推理共同优化的可学习过程，而非外部编排的被动对象。

## 7. 优点

- **问题定位清晰**：对现有三大技能演化范式进行了系统归纳，指出各自核心缺陷，并据此推导出"元技能应作为可学习智能体与推理联合训练"的设计原则，逻辑链条完整。
- **方法设计新颖且统一**：将"元技能固定工作流"重定义"为 RL 可训练的元技能代理"，并实现共享骨干、异构角色、分层技能库的整体协同——是目前少见的技能-策略端到端共同进化方案。
- **信用分配设计精细**：
  - 使用编辑后验证（post-edit verification）作为延迟奖励，基线相减控制任务难度；
  - GiGPO 的双层组内相对优势区分 episode 级与 step 级信用；
  - 两角色统计量分别归一化，避免技能验证奖励与推理奖励尺度混淆。
- **库增长控制合理**：验证通过才晋升 + 组内 top-k 限制，兼顾连续性与容量界。
- **实验与伪代码详尽**：算法伪代码、提示词均完整给出；主结果、消融、动力学分析、案例分析互为支撑，展示了方法在算法层面与现实案例层面的双可解释性；程序运行时长约 526 GPU-hours，对比其效果提升，成本相对合理。
- **性能提升明确且可复现鼓励**：代码已开源，便于社区验证。

## 8. 不足与局限

- **评测场景较窄**：仅在 ALFWorld（文本家务）和 WebShop（模拟电商）两个合成环境验证，未涉及更复杂、真实世界的长程任务（如代码开发、真实网页操作、具身环境）；对 "长期 horizon 任务" 的实际复杂度代表性有限。
- **消融实验覆盖不全面**：消融只在 ALFWorld 单环境单任务混合设置；WebShop 未出消融数据，导致方法对另一个 benchmark 的组件贡献不清楚。具体任务类型的消融表现也未呈现。
- **基线公平性风险**：表 1 中许多基线数字引用其他论文结果，在骨干模型、训练预算、验证集划分和评估协议上未必与 CoSkill 对齐；虽然附录 E 尝试注明，但从已发表表格互相摘取数值在严格可控比较上仍属弱论证。
- **外部模型介入初始化**：初始技能库是由外部 LLM（固定策略）离线收集 rollouts 生成的，若外部策略质量或覆盖不足会直接影响后续 RL 效果；文中未对此做敏感性分析。
- **验证尝试的计算开销未充分讨论**：每次 rollout 后额外执行 \(M\) 次验证尝试（本文 \(M=1\)），虽提高数据质量，但意味着约一倍的量纲 rollout 成本；66 小时挂钟仅是 ALFWorld，训练总开销-性能性价比分析较粗略。不同最佳超参数（如 \(M\)、演化序列长度、\(K_{prom}\)）未做参数敏感性分析。
- **上下文窗口限制的潜在影响**：随技能库持续演化，检索多样性、编辑序列的稳定性在更长训练周期或更大任务集上的表现未被充分测试；虽然库有容量上限与修剪策略，但长程运行的退化模式仍需进一步检验。
- **角色异质动作空间下的策略共享局限**：同一 LLM 权重同时承担"环境动作生成"与"技能编辑 JSON 返回"两种任务，prompt 引导可能造成策略冲突的干扰；文中没有对该耦合是否会损害单角色性能做进一步剖析。
