## 摘要
在面向用户的产品中可靠地部署LLM智能体，并不取决于原始的任务解决能力，而是取决于一致性和限制感知：在重复试验中表现相同，并且能够识别请求何时无法、或尚无法被安全地完成。CAR-bench在车载助手领域暴露了这种可靠性差距：一个由LLM模拟的用户提出不完整或模糊的请求，要求智能体通过多轮对话和工具使用来解决不确定性，同时严格遵守领域政策。即使是前沿模型，在其至少能解决一次的能力（Pass@3）与跨试验一致解决的能力（Pass^k）之间也显示出显著差距。我们通过TRACE（轨迹对比进化，TRAjectory-Contrastive Evolution）弥合了这一差距，该方法在不修改模型权重的情况下，迭代式地改进基于技能的智能体的行为知识。这些知识被组织为一个模块化、可检索的技能库（Skill Bank），每个技能编码一套自包含的工具使用规则和行为指南。TRACE通过一个智能体自进化循环来进化这个技能库：在每轮评估后，它根据调用的技能对轨迹进行分组，并通过对比成功与失败的行为来细化每个技能。更新后的技能库随后指导后续轮次，而在部署期间，Actor在每一步执行状态条件化的技能编排。在GPT-5.5上，TRACE将一致性（Pass^3）提高了34.6个百分点，从59.9%提升至94.5%，同时将潜在性能与可靠性能之间的差距缩小至仅4.0个百分点。在官方隐藏测试集上，TRACE使用GPT-5.6-Sol取得了第一名，Pass^3得分达到70%，相比基线相对提升40%。这些结果表明，TRACE将高模型潜力转化为稳定、一致的性能提升。项目主页：https://darwin-agent.github.io/Car-bench-TRACE。

## Abstract
Reliable deployment of LLM agents in user-facing products depends not on raw task-solving ability but on consistency and limit-awareness: behaving the same way across repeated trials, and recognizing when a request cannot, or cannot yet, be safely fulfilled. CAR-bench exposes this reliability gap in the domain of in-car assistants: an LLM-simulated user issues incomplete or ambiguous requests, requiring the agent to resolve uncertainty through multi-turn dialogue and tool use while strictly adhering to domain policies. Even frontier models show a substantial gap between what they can solve at least once (Pass@3) and what they solve consistently across trials (Pass^k). We bridge this gap with TRACE (TRAjectory-Contrastive Evolution), which iteratively improves a skill-based agent's behavioral knowledge without modifying model weights. This knowledge is organized as a Skill Bank of modular, retrievable skills, each encoding a self-contained set of tool-use rules and behavioral guidelines. TRACE evolves this bank through an agentic self-evolution loop: after each evaluation round, it groups trajectories by the skills invoked and refines each skill by contrasting successful and failed behaviors. The updated bank then guides subsequent rounds, while during deployment the Actor performs state-conditioned skill orchestration at every turn. On GPT-5.5, TRACE improves consistency (Pass^3) by 34.6 points, from 59.9% to 94.5%, while shrinking the gap between potential and reliable performance to just 4.0 points. On the official hidden set, TRACE achieved first place using GPT-5.6-Sol, attaining a Pass^3 score of 70%-a 40% relative improvement over the baseline. These results show that TRACE converts high model potential into stable, consistent performance gain. Project homepage: https://darwin-agent.github.io/Car-bench-TRACE.

# TRACE：一种用于一致性、限制感知型LLM智能体的自进化技能库

## 1. 核心问题与整体含义

**研究动机与背景：**

- 面向用户产品（如车载助手）中部署LLM智能体，核心挑战不是**原始任务解决能力**，而是两个安全关键属性：
  - **一致性（Consistency）**：在重复试验中产生稳定、可复现的行为表现。
  - **限制感知（Limit-awareness）**：识别请求何时无法（或尚无法）被安全完成，而非编造不存在的成功。
- 现有LLM存在"**完成-合规张力**"（completion-compliance tension）：模型倾向于优先满足用户请求而非遵循领域政策、主动澄清或承认能力不足。
- 这种失败是**间歇性**的——同一智能体可能一次成功、一次失败，导致"潜在一贯性"（Pass@k）与"可靠一贯性"（Pasŝ k）之间存在显著差距。
- CAR-bench基准为此而设：LLM模拟用户发出不完整/模糊/不可满足请求，要求智能体通过多轮对话、工具调用和领域政策合规来完成任务，即使前沿模型也在此暴露可靠性差距。

## 2. 方法论

**核心思想：**

TRACE（TRAjectory-Contrastive Evolution）将行为知识组织为**模块化、可检索的技能库（Skill Bank）**，通过**轨迹对比**方式自进化技能库，在不修改模型权重的前提下，将高模型潜力转化为稳定一致的表现。

**关键技术细节：**

- **技能库的结构**：每个技能 $s_i = (d_i, b_i)$，其中 $d_i$ 为一行描述（路由线索），$b_i$ 为工具使用规则与行为指南的正文（Markdown 格式）。

- **技能库初始化（分层抽象 + 分解）**，遵循 $B_{task} \rightarrow B_{type} \rightarrow B_{op} \rightarrow B^{(0)}$ 的流程：
  - *任务级蒸馏*（Task-Level Distillation）：每个任务的跨试轨迹浓缩为任务级技能。
  - *类型级聚合*（Type-Level Aggregation）：合并同任务类型的技能，移除任务特化细节。
  - *操作级抽象*（Operation-Level Abstraction）：跨任务类型按底层操作（如"车窗控制""气候调节"）合并，实现知识迁移。
  - *技能分解*（Skill Decomposition）：将宽泛技能拆为细粒度技能，确保每次激活精确、专注的指导。

- **轨迹对比式技能进化（核心循环）**：每轮评估后执行更新 $B^{(r+1)} = \Phi(B^{(r)}, T^{(r)})$，包含三个步骤：
  1. **技能感知分组**（Skill-Aware Grouping）：按轨迹调用的技能将轨迹聚类，无技能/未知技能轨迹单独存放。
  2. **部署忠实重建**（Deployment-Faithful Reconstruction）：区分"部署期间可见"信息与"仅进化期可用"信息，避免技能依赖部署时不可见的知识。
  3. **对比式技能精炼**（Contrastive Skill Refinement）：成功轨迹与失败轨迹配对对比，编辑现有技能以吸收教训；无技能轨迹中的可复用模式则挖掘新技能；最终通过验证移除任务标识符、记忆化答案和环境特定值（**去硬编码约束**）。

- **状态条件化技能编排（部署阶段）**：
  - 每轮对话状态 $h_t$ 下，Actor 对所有技能描述 $\{d_i\}$ 进行评估并生成**有序技能序列** $S_t = \sigma(h_t, \{d_i\})$。
  - 按序提取技能正文并组合进上下文 $c_t$，采样动作 $a_t$。
  - **每轮重新编排**：$S_{t+1}$ 与 $S_t$ 无关，保持上下文精简并让技能跟随对话演进。

## 3. 实验设计

**Benchmark：** CAR-bench

- 场景：车载助手（in-car assistant），LLM模拟用户 + 58个互连工具 + 19条领域政策。
- 任务类型三种：
  - **Base任务**：常规任务完成。
  - **Hallucination任务**：移除必需工具/参数/结果，要求智能体承认能力缺失而非虚构。
  - **Disambiguation任务**：引入受控歧义，应内部消化或必要时向用户澄清。

**评估指标：**

- **Pasŝ k**：任务在k次试验中全部成功（可靠性）。
- **Pass@k**：任务在k次试验中至少一次成功（潜在能力）。
- **一致性差距 Δk = Pass@k − Pasŝ k**（越小越好）。

**对比设置：**

- 两个骨干模型：**GPT-5.5（medium推理强度）** 与 **GLM-5.2（high推理强度）**。
- 技能库仅用GPT-5.5轨迹进化，**原样应用于GLM-5.2**，检验跨骨干迁移。
- 对比配置：baseline（默认提示+原生工具调用）vs. TRACE（叠加技能库）。

**训练/测试划分：** 在训练集上自举技能库，在测试集上扩展覆盖，最终在合并数据集上报告；另设官方隐藏集（30个任务，3次/任务）独立评估。

## 7. 优点与亮点

1. **模型无关、无需权重修改**：通过纯行为脚手架改进，兼容任何基础模型。
2. **操作级技能组织**：使知识可跨任务类型迁移，而非任务死记硬背。
3. **轨迹对比机制**：同时利用成功与失败轨迹，从错误中提炼可复用的"避坑"知识。
4. **部署忠实重建**：严格区分进化期与部署期信息可及性，避免技能依赖特权信息。
5. **去硬编码约束**：禁止技能编码任务ID、记忆答案或环境特定值，保障泛化。
6. **每轮状态条件化编排**：技能序列随对话状态动态刷新，而非一次性静态检索。
7. **严格的公平对比**：baseline与TRACE共享同一模型、提示、工具调用，唯一差异在于技能编排，归因清晰。
8. **隐藏集验证**：证明技能库泛化而非记忆。

## 8. 不足与局限

1. **编排器扩展性受限**：当前编排器由LLM逐轮评估所有技能描述，技能库扩大时成本线性增长，可扩展性差（作者自述），需学习式或分层编排器。
2. **无部署期反馈闭环**：技能库是前馈指导，部署期间无任务执行反馈回写技能，无法对话中自适应纠正（作者自述）。
3. **算力开销偏高**：token消耗（+72.4%）与成本（+58.8%）增幅显著。
4. **消融实验缺失**：未单独验证各组件（如操作级抽象、去硬编码约束）的独立贡献。
5. **实验场景局限**：仅一个benchmark（CAR-bench车载场景）；仅在两个商业闭源模型上验证；未涉及开源模型或小型模型。
6. **技能库进化来源单一**：仅用GPT-5.5轨迹进化，未探索多源轨迹、多模型共同进化等方案。
7. **指标角度局限**：Pasŝ 3以全有或全无为标准，未报告部分成功、安全性违规严重程度等细粒度信号。
8. **泛化性证据有限**：虽然隐藏集有所验证，但仍属同一基准分布；对其他领域（如软件工程、通用助手）的适应能力未知。
