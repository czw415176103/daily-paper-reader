## 摘要
基于LLM的多智能体系统在复杂任务上表现出色，但如何从交互经验中持续改进仍然具有挑战性。现有的自我反思方法构建经验记忆，但这些记忆大多难以调用、精炼或扩展，而智能体技能提供了一种更具可操作性的单元：结构化的程序性知识，它规定了何时行动、如何行动以及使用哪些资源或工具。我们提出了MASkills，一种通过智能体技能优化多智能体LLM系统的持续学习框架。MASkills提出了一种新的智能体优化流程，整合了技能条件信用分配、层级信用聚合和动量平滑优化，使智能体技能库能够通过精炼、归纳、整合和剪枝进行演化。在HotpotQA、LoCoMo和GAIA上的实验证明了MASkills在多种智能体任务上的有效性。我们的代码可在https://github.com/DaRL-GenAI/MASkills获取。

## Abstract
LLM-based multi-agent systems have shown strong performance on complex tasks, yet continual improvement from interaction experience remains challenging. Existing self-reflection methods build experience memories, but memories are mostly hard to invoke, refine, or scale, while agent skills offer a more actionable unit: structured procedural knowledge that specifies when to act, how to act, and which resources or tools to use. We introduce MASkills, a continual learning framework that optimizes multi-agent LLM systems through agent skills. MASkills presents a new agent-optimization pipeline that integrates skill-conditioned credit assignment, hierarchical credit aggregation, and momentum-smoothed optimization, enabling agent skill libraries to evolve through refinement, induction, consolidation, and pruning. Experiments on HotpotQA, LoCoMo, and GAIA demonstrate the effectiveness of MASkills across multiple agentic tasks. Our code is available at https://github.com/DaRL-GenAI/MASkills

- **研究问题**：如何将技能演化（Skilling Evolution）从单智能体场景扩展到多智能体系统？这面临三个新挑战：

  2. **反馈噪声大**：语言化反馈在不同轨迹间常互相冲突、不稳定；此外系统可能存在中心化、去中心化等异构协调拓扑，导致信用传播路径复杂。
  3. **离散且高风险的更新**：技能是语言工件（如SKILL.md），无法进行数值平滑更新，只能做离散的结构性修改，编辑错误可能直接污染智能体的行动空间，导致性能崩溃。

## 2. 方法论（MASkills框架）
- **总体范式**：将多智能体策略优化从“参数空间”迁移到“技能空间”。论文借鉴TextGrad与LangMARL的阐释，构建了一个**语言空间中的策略梯度类比框架**：轨迹采样类比策略执行；语言批评者输出“优势”信号；层级聚合与动量平滑类比期望估计与方差缩减；四种技能演化算子充当“伪梯度”更新。
- **核心流程（四步闭环）**：
  1. **多智能体技能执行**：每个智能体本地维护一个技能库。在互动时，系统仅向LLM提示技能轻量级元数据（skill.yaml），当智能体选择激活某个技能时，才动态加载其SKILL.md及辅助资源等。技能调用路径可以利用平台提供的工具调用机制清晰记录。策略被形式化为：$a_i^t \sim \pi_\theta(\cdot | o_i^t, \mathcal{K}_i, h_i^t)$。
  2. **细粒度技能信用分配**：由语言批评者针对每个被调用的技能 $k$ 输出结构化自然语言信用评价 $C_i^{text}(\tau, k)$（通过反事实比较：假设该技能未被使用，结果将如何变化？）。批评者同时还会生成一个“残差信用” $C_i^{text}(\tau)$，用于捕捉无法归因于现有技能的系统级效应（提示是否需要归纳新技能）。
  3. **稳定化语言梯度下降**：
     - 生成编辑方向：先由LLM将逐技能信用评论转为具体的轨迹级编辑方向 $g_i(\tau,k)$；
     - 层级聚合：LLM沿轨迹、技能、智能体、拓扑四个维度进行递归聚合（$G_i^{(m)}(k) = \text{LLM\_Agg}(\{g_i(\tau_b,k)\}_{b=1}^B)$），合并共性模式、解决冲突、去除冗余；
     - 动量平滑：将历史编辑轨迹与当前聚合结果合并，利用类似动量机制抑制瞬时噪声，形成稳定一致的演化信号。
  4. **信用驱动的技能演化算子**（内含保障机制）：
     - **Refinement（精炼）**：对“有用但不够好”的现有技能执行局部增量修补（根据当前方向 $G_i^{(m)}(k)$ 进行最小化干预，保留既有可复用结构）；
     - **Induction（归纳）**：当现有技能库无法解释某些持续性失败或缺失性能力时，系统从困难轨迹中通过 LLM 提出归纳全新的技能工件（$k_{new} \sim \text{LLM\_Propose}(\mathcal{H}_i, G_i^{(m)})$）
     - **Consolidation（整合）**：周期性的将功能重叠的技能进行合并（$k_{macro}=\text{LLM\_Merge}(k_a,k_b,\ldots)$），防止库爆炸与碎片化；
     - **Pruning（剪枝）**：依据编辑方向与使用频率信号，剔除长期低效用、冗余或过时的技能；
     - **Validation & Rollback（验证与回滚）**：保证技能库的演化安全，所有候选更新需在保留验证集上评估，只有当预估回报不下降超过容忍值（$\hat{J}_{val}(\mathcal{K}'_i) \geq \hat{J}_{val}(\mathcal{K}_i)-\delta$）时才能通过验证并入库。
