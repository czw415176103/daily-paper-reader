## 摘要
自我进化框架通常优化任务解决方案，同时将周围的框架视为固定不变。我们引入了框架感知的自我进化（HASE），这是一种基于智能体的强化学习框架，其中单个模型可以在多轮动作空间中生成任务解决方案或编辑选定的框架组件。HASE使得单个Qwen3-8B模型能够匹配使用Claude Code作为框架提出者的GPT-OSS-120B模型的文本分类性能。在alpha因子挖掘中，HASE超越了已报道的GPT-OSS-120B基线。HASE还能修复不完善的评估组件，并在圆填充算法发现中收敛到最先进的性能。这些结果表明，HASE通过统一的智能体过程改进了框架和解决方案。

## Abstract
Self-evolving frameworks usually optimize task solutions while treating the surrounding harness as fixed. We introduce Harness-Aware Self-Evolving (HASE), an agentic reinforcement-learning framework in which a single model can generate task solutions or edit selected harness components in a multi-turn action space. HASE enables a single Qwen3-8B model to match the text-classification performance of a GPT-OSS-120B model that uses Claude Code as the harness proposer. In alpha factor mining, HASE outperforms the reported GPT-OSS-120B baseline. HASE also repairs imperfect evaluation components and converges to state-of-the-art performance in circle-packing algorithm discovery. These results show that HASE improves the harness and the solution through one unified agentic process.

### 1. 论文的核心问题与整体含义
现有自我进化系统（如 FunSearch、AlphaEvolve、ThetaEvolve 等）通常假设外围框架（Harness）固定不变，仅优化对象级任务解。这种固定假设导致两个局限：  
- 人工编写的评估器可能不完整或被利用，模型可能因追求分数而钻空子，而非真正解决问题。  
- 指导框架（如提示词、记忆、检索策略）提供的搜索先验差，限制了性能提升。  
本文提出 **Harness-Aware Self-Evolving (HASE)**，让单一模型在同一多步动作空间中既能生成任务解，也能编辑选定的框架组件（包括引导组件和评估组件），实现模型权重、框架与任务解的共同进化。其核心意义在于：通过统一的智能体过程同时改进“工作环境”和“解决方案”，无需依赖外部强大代码生成模型。

### 2. 方法论
#### 核心思想
- 将框架分为两类：  
  - **引导组件**（Guidance）：prompt、记忆格式、检索脚本、上下文选择等，用于提升搜索质量。  
  - **评估组件**（Evaluation）：局部验证器/评分器，定义解的合法性与指标；可被编辑，但修改受限于真实环境评估器（Oracle）的反馈，防止奖励破解。  
- 动作空间统一：模型可以提交任务解（如代码）或使用沙箱命令（`ls`、`cat`、`grep`、`replace`、`overwrite`）检查并修改可编辑框架文件。  
- 训练使用 **GRPO**（Group Relative Policy Optimization），奖励仅基于最终提交的解的质量，不直接奖励框架编辑动作。  
- **阶段级审查**（Phase-level Review）：每个训练阶段结束后，收集候选编辑，通过过滤、排序和验证集评估，仅提交能提升验证性能的稳定更新。对于评估组件编辑，还需满足与真实评估器的一致性（通过错配集 `M` 驱动）。  

#### 算法流程（Algorithm 1）
1. 初始化策略 `πθ` 和持久框架 `h`。  
2. 对于每个阶段 `p`：  
   - 初始化阶段候选池 `Cp`。  
   - 执行多个 GRPO epoch，每个 epoch 滚动多步轨迹（可编辑框架、提交解）。  
   - 使用局部评估器 `Eloc` 为提交的解打分，赋予轨迹奖励，并通过 GRPO 更新策略参数。  
   - 收集解析成功且获得正概念验证（PoC）的引导编辑到 `Cp`。  
   - 若允许评估组件进化，查询真实评估器 `Ereal`，将不一致的案例加入 `M`，并根据 `M` 审查评估编辑。  
   - 阶段结束时审查 `Cp` 中的引导编辑，选出最佳稳定更新写入持久框架 `h`。

### 6. 主要结论
- HASE 使 8B 模型在文本分类上达到 GPT-OSS-120B + Claude Code 的性能（86.98% vs 86.8%）。  
- 在 Alpha 因子挖掘中，HASE 的 8B 模型在 RankIC、ICIR、AER、IR 等指标上全面超越 GPT-OSS-120B 基线（IR 1.70 vs 0.80）。  
- 在圆填充和 Heilbronn 三角形中，HASE 能从有缺陷的评估器出发，自动修复漏洞，并最终达到或超越定制化算法的 SOTA（圆填充 2.635983，Heilbronn 0.036082）。  
- 权重共同进化是必要且有效的：冻结权重时性能停滞在 0.0219，而共同进化后提升至 0.0361。  
- 整体表明：统一框架感知的自我进化能有效提升小模型系统的整体能力。

### 7. 优点
- **统一性**：单一模型同时承担解生成和框架编辑，无需外部强大代码提出者，降低系统复杂度。  
- **安全性**：对引导组件和评估组件有不同治理规则，评估修改必须由真实环境反馈驱动，防止奖励破解。  
- **泛化性**：在文本、金融、几何优化等多个任务验证，且能处理评估器初始缺陷。  
- **低成本**：仅需 8B 模型和少量 GPU 即可在多项任务上超越或匹配大模型方案。  
- **可解释性**：提供了评估器修复的渐进式示例（圆填充），展示代理分数与真实分数对齐过程。

### 8. 不足与局限
- **比例/通用性**：未在大规模多任务或更大模型（如 70B+）上进行系统缩放研究，当前结论局限于 8B 规模。  
- **工程保守性**：可编辑组件被白名单限制，评估编辑必须满足严格触发条件，可能拒绝有益但更激进的修改。  
- **评估组件修复的覆盖范围**：错配集只包含已发现的案例，不能保证全局正确性（未来可能出现新的漏洞）。  
- **资源与复现**：部分算力细节未充分披露（如 S2D 和 Alpha 的确切 GPU 型号），可能影响复现。  
- **风险**：如果真实评估器本身存在缺陷或访问成本高，HASE 的修复过程可能效果受限。
