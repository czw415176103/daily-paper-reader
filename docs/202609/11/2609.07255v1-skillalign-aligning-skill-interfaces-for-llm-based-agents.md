## 摘要
语言模型智能体日益依赖技能：用于推理、工具使用和交互的可复用程序性知识。现有工作研究了技能如何被获取、检索、压缩或组合，但通常假设一旦选定某个技能，其与智能体的接口便是固定的。我们认为，这忽略了一个技能效用的关键来源：同一个技能可能因呈现方式不同而产生帮助、干扰或误导作用。我们提出 SkillAlign，一个与提供方无关的框架，将候选技能表示为多视图程序性卡片，并通过可选的呈现接口进行渲染，包括完整指令、提示、压缩摘要、工作流或不呈现。这支持反事实评估：任务、智能体和候选技能固定不变，仅改变呈现接口。在 ALFWorld 和 SkillsBench 上，我们表明呈现形式会显著影响任务成功率和渲染上下文成本，并且紧凑的 top-k 呈现可以优于全库注入。我们进一步在 ALFWorld 上进行基于回放的政策学习分析，表明自适应呈现包含可学习信号，但仍远未达到 oracle 选择。我们的结果表明，技能增强的智能体不仅应优化使用哪些技能，还应优化这些技能如何呈现。

## Abstract
Language-model agents increasingly rely on skills: reusable procedural knowledge for reasoning, tool use, and interaction. Existing work studies how skills are acquired, retrieved, compressed, or composed, but often assumes that once a skill is selected, its interface to the agent is fixed. We argue that this overlooks a key source of skill utility: the same skill can help, distract, or mislead depending on how it is exposed. We propose SkillAlign, a provider-agnostic framework that represents candidate skills as multi-view procedural cards and renders them through alternative exposure interfaces, including full instructions, hints, compressed summaries, workflows, or no exposure. This enables counterfactual evaluation where the task, agent, and candidate skills are fixed while only the exposure interface varies. Across ALFWorld and SkillsBench, we show that exposure form substantially affects task success and rendered context cost, and that compact top-k exposure can outperform full-library injection. We further conduct a replay-based policy-learning analysis on ALFWorld, showing that adaptive exposure contains learnable signal but remains far from oracle selection. Our results suggest that skill-augmented agents should optimize not only which skills to use, but also how those skills are presented.

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体日益依赖“技能”（可复用的程序性知识）来完成推理、工具使用和交互。现有工作主要关注技能的获取、检索、压缩、组合或演化，但普遍默认：一旦技能被选中，其暴露给智能体的接口是固定的。
- **核心问题**：论文指出，同一个技能可能因“呈现方式”不同而帮助、干扰或误导智能体。技能是否有效，不仅取决于其内容或相关性，还取决于它以何种接口条件化智能体。
- **整体含义**：SkillAlign 将“技能暴露”从隐含的格式选择提升为一等决策变量。技能增强智能体不应只优化“用哪些技能”，还应优化“这些技能如何呈现”。
- **框架定位**：SkillAlign 是 provider-agnostic 的暴露层，位于上游技能提供方（如全库、向量检索、图检索、oracle 标注）与下游智能体交互循环之间，不替代检索，而是补充检索。

## 2. 方法论

### 2.1 核心思想

- 将任务上下文记为 \(x\)，智能体上下文记为 \(a\)，候选技能集合记为 \(S_x=\{s_1,\dots,s_k\}\)。
- SkillAlign 不优化技能检索本身，而是选择暴露接口：
  \[
  m=\pi(x,a,S_x),\quad m\in M
  \]
  并将同一候选技能渲染为面向智能体的上下文：
  \[
  r=\mathrm{Render}(S_x,m;x,a)
  \]
- 渲染结果 \(r\) 不替换或修改原始技能工件，而是作为推理时技能条件化智能体的接口。

### 2.2 多视图程序性卡片

- 每个原始技能被表示为多视图技能卡：
  \[
  c(s)=\{v_{\text{full}},v_{\text{hint}},v_{\text{comp}},v_{\text{flow}},\eta\}
  \]
- 各视图语义不同，而非仅长度不同：
  - `full`：原始技能内容，保留执行关键细节、脚本、参数、假设、边界情况。
  - `hint`：简短的任务面向线索，作为弱激活信号。
  - `compressed`：压缩的操作性摘要，涵盖适用性、动作、预期输出和不匹配风险。
  - `workflow`：有序工作流视图，强调步骤顺序、检查点和停止条件。
  - `η`：元数据，如技能 id、来源、路径、检索摘要。

### 2.3 暴露接口集合

- 主实验使用五种接口：
  - `none`：不暴露技能文本。
  - `full`：暴露原始技能文档。
  - `hint`：仅暴露一条简短行动线索。
  - `compressed`：暴露触发条件、输入/状态、核心动作、预期输出和风险。
  - `workflow`：暴露有序步骤、验证点和停止条件。
- 注入时使用统一 wrapper，提示智能体将技能视为“可选支持”，而非忽略当前观察的硬命令。

### 2.4 反事实评估协议

- 固定任务、智能体后端和候选技能，仅改变暴露接口，得到反事实轨迹集合：
  \[
  \{\tau_m^x:m\in M\}
  \]
- 若同一任务、后端和候选技能下，不同接口导致性能变化，则说明接口是实质性因素，而非装饰性格式。
- 负迁移定义：无暴露运行成功但接口 \(m\) 失败，或标量奖励下降。

### 2.5 探索性暴露策略学习

- 对每个任务和候选集，将固定接口结果转为效用分数：
  \[
  U_x(m)=R_x(m)-\alpha C_x(m)-\beta T_x(m)
  \]
  其中 \(R_x(m)\) 为奖励/成功，\(C_x(m)\) 为归一化上下文成本，\(T_x(m)\) 为归一化轨迹长度。
- 最高效用接口作为 SFT 标签；效用差距足够大的接口对作为 DPO 偏好样本。
- 策略输入任务描述、候选技能卡内容和来源元数据，输出单个接口标签。
- 实验中在 Qwen3-4B 上训练轻量 LoRA 适配器；该部分被作者定位为可行性验证，而非完整解决方案。

## 3. 实验设计

- **基准与场景**：
  - **ALFWorld**：文本具身环境，多步家庭任务，ReAct 风格文本设置，140 个评估 episode，最多 30 步。
  - **SkillsBench**：真实技术任务与 curated skills，覆盖数据分析、科学计算、金融建模、工程工作流等，94 个容器化任务实例，使用 Harbor 和 Terminus-2 执行框架。
  - **ScienceWorld**：用于辅助生成暴露策略数据。
- **技能库规模**：
  - 主实验使用 `skills_1000`。
  - 缩放分析额外使用 `skills_200`、`skills_500`、`skills_2000`。
- **候选技能来源**：
  - `none`：无技能上下文。
  - `all`：全技能库可用，不做任务特定过滤。
  - `vector-top k`：基于语义相似度检索，ALFWorld 取 \(k=5\)，SkillsBench 取 \(k=8\)。
  - `Graph-top k`：结构化图检索提供方，使用 Graph-of-Skills 作为代表，用于验证暴露效应是否在结构化选择下持续。
- **智能体后端**：
  - `minimax-m2.7`
  - `gpt-5.3-codex`
  - `glm-5`
- **指标**：
  - ALFWorld 报告成功率（SR），SkillsBench 报告平均奖励（AR）。
  - 同时报告渲染技能上下文成本 \(C\)，即渲染技能上下文的 token 长度，以千 token 计。
- **对比方法**：
  - 固定暴露接口：`none`、`full`、`hint`、`compressed`、`workflow`。
  - 候选来源对比：无技能、全库、向量 top-k、图 top-k。
  - 策略学习对比：最佳固定接口、SFT 策略、DPO 策略、oracle 暴露。
  - 附加对照：通用长度匹配摘要（Generic Summary）对比结构化 `compressed`。
  - 人工保真审计：检查生成视图的任务相关遗漏、扭曲、矛盾和误导性添加。
