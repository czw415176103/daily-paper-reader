## 摘要
智能体自我进化主要关注学习如何行动，却忽视了一个同样重要的能力：学习发现智能体所不知道的事物。现有方法通常假设失败发现是给定的，专注于在失败被识别后如何修复。我们质疑盲点诊断本身是否可以被学习。为此，我们将诊断作为与执行分离的智能体能力来研究，并排除两种替代进展来源：执行器适应和人类监督。在这些约束下，性能无法通过执行器更新或带注释示例来提升，迫使所有改进都源于学习到的诊断能力。我们提出SkillMentor，它通过强化学习训练一个Mentor策略，以生成诊断任务、识别反复出现的失败模式，并将其整理为可复用的纠正技能。在AppWorld和BFCLv3上，SkillMentor将执行器性能平均提升了44.2%。这些结果表明，盲点诊断是一种可学习的能力，使得无需更新执行器权重或依赖人工整理数据即可实现自我进化。

## Abstract
Agent self-evolution has primarily focused on learning how to act, while overlooking an equally important capability: learning to discover what an agent does not know. Existing approaches typically assume that failure discovery is given, focusing on how to repair failures once they are identified. We ask whether blind-spot diagnosis itself can be learned. We thus study diagnosis as an agent capability separate from execution, and exclude two alternative sources of progress: executor adaptation and human supervision. Under these constraints, performance cannot improve through executor updates or annotated examples, forcing all improvements to originate from the learned diagnostic capability. We propose SkillMentor, which trains a Mentor policy via reinforcement learning to generate diagnostic tasks, identify recurrent failure modes, and curate them into reusable corrective skills. Across AppWorld and BFCLv3, SkillMentor improves executor performance by an average of 44.2%. These results suggest that blind-spot diagnosis is a learnable capability, enabling self-evolution without updating executor weights or relying on human-curated data.

## 2. 方法论：SkillMentor

### 2.1 核心思想

- 训练一个**Mentor策略 πθ**（小模型，如Qwen3.5-4B），通过强化学习（GRPO）主动发现执行器（Executor πE）的盲点，并生成纠正技能存入外部技能仓库。
- **盲点定义**：元组 b = (T, c)，其中 T 是执行器持续表现不佳的任务，c 是可缓解该失败的纠正技能。
- **核心创新**：将诊断形式化为策略优化问题，通过**发现-整理联合优化**形成正反馈闭环——更好的发现产生更好的技能，更好的技能暴露新的盲点。

### 2.2 三个关键阶段

1. **盲点发现（Blind-Spot Discovery）**
   - Mentor在环境中自由探索，生成探索轨迹；
   - 维护多样性缓冲区（diversity buffer）防止探索坍缩；
   - 从轨迹中合成 G 个候选诊断任务 Qₜ = {q₁, ..., q_G}。

2. **差距评估（Gap Evaluation）**
   - 每个诊断任务由强参考模型 M 和执行器 πE 分别执行，获得分数 sᴹᵢ 和 sᴱᵢ；
   - **诊断差距**：δᵢ = max(0, sᴹᵢ − sᴱᵢ)，即发现奖励 r_disc；
   - 选择差距最大的任务 q_max 进入技能整理阶段；
   - 使用**线性衰减阈值**（0.5 → 0.2，每步 −0.002），以匹配随技能累积而自然缩小的差距分布。

3. **技能整理（Skill Curation）**
   - Mentor生成 G 个候选技能，支持三种操作：**ADD（新增）、UPDATE（更新）、MERGE（合并）**；
   - 双重验证：**语法有效性**（符合预定义Markdown格式）+ **执行器验证效用**（执行器retry验证Δ = s_c − sᴱ_max 是否 > 0.5）；
   - 整理奖励：r_curate = 0.3·f(c) + 0.7·Δ；
   - 轻量 **DELETE 机制**：检索成功率低于0.05的技能被淘汰。

### 2.3 训练目标

- 使用 **GRPO** 联合优化两个奖励：
  \[
  J_{GRPO}(θ) = J_{disc} + J_{curate} − βD_{KL}(π_θ ∥ π_{ref})
  \]
- 发现奖励提供主要学习信号，整理奖励将诊断转化为可复用技能；
- 两者通过演化的技能仓库耦合，共享Mentor参数（消融证明共享优于分离）。

### 2.4 推理与能力边界迁移

- 推理时执行器根据任务描述检索相关技能并前置到提示中；
- 随着技能积累，执行器的能力边界持续迁移，诊断阈值随之衰减，形成自我进化循环。

## 6. 主要结论与发现

1. **诊断是可学习的**：RL训练的Mentor在所有执行器和Benchmark上稳定超越提示式Mentor，平均相对提升44.2%（AppWorld与BFCLv3平均）；
2. **学习胜于规模**：4B RL-Mentor持续击败DeepSeek-V4-Flash等更大提示式模型，诊断能力不是模型规模的副产品；
3. **弱执行器受益更大**：DeepSeek-R1-Distill-Qwen-7B相对提升最大（+46.6%），Qwen3.5-9B最小（+36.7%），符合盲点作为程序性缺陷的定义；
4. **发现与整理必须联合优化**：移除发现奖励损失最大（0.351→0.292），共享参数优于分离参数（0.351 vs 0.336）；
5. **技能可跨执行器迁移**：弱执行器学到的技能对强执行器高度有效，强执行器学到的技能对弱执行器覆盖不足；
6. **盲点是非平稳的**：修复旧盲点会暴露新盲点，衰减阈值优于静态和上升阈值；
7. **技能库天然可解释**：Markdown技能文件构成执行器缺陷的可读地图，便于检查、编辑和转移。

## 7. 优点

- **问题定位新颖**：首次将“诊断”显式分离为独立可学习能力，而非执行训练的附带品；
- **实验隔离设计精巧**：冻结执行器+零人工数据的设计将诊断隔离为唯一改进来源，逻辑严密；
- **反馈回路建模完整**：发现→修复→新盲点暴露的正反馈循环，以联合RL优化实现，而非工程启发式；
- **强模型依赖极轻**：LLM Judge训练时唯一使用、部署时完全移除，且替换Judge性能鲁棒（0.338~0.361），成本差异大（¥32~¥349）；
- **可迁移且可解释**：技能以人类可读Markdown存储，跨模型迁移矩阵验证了通用诊断知识的价值；
- **阈值自适应设计**：线性衰减阈值匹配盲点分布随修复动态缩小的趋势，细节考究。

## 8. 不足与局限

- **环境覆盖有限**：仅两个合成Benchmark（AppWorld/BFCLv3），均为标准化API环境，未验证真实网页、代码库、多模态等复杂场景；
- **短期训练视野**：仅200训练步，长期（千步级）演化中技能库膨胀、冲突、遗忘等问题未研究；
- **评价依赖LLM Judge**：诊断差距完全基于强模型打分，Judge的偏见可能被反馈回Mentor策略（尽管鲁棒性实验有所缓解）；
- **Mentor规模单一**：未探索Mentor规模对诊断能力的影响，无法回答“诊断能力是否存在规模门槛”；
- **技能上限受强模型能力约束**：Mentor生成的技能不会超过参考模型能识别的失败模式，强/弱参考模型的系统性偏差值得进一步研究；
- **DELETE阈值与技能生命周期管理较粗糙**：仅以0.05成功率驱逐，未考虑技能区分度、重叠、时效性等因素；
- **实际应用差距**：跨执行器迁移实验中，所有执行器均为Qwen/相近系列（及少数7B模型），未验证跨家族大跨度迁移（如LLaMA→GPT系列）。
