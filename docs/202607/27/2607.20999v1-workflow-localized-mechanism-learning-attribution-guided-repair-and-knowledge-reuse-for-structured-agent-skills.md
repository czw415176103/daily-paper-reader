## 摘要
智能体技能将可复用的程序性知识封装为外部制品，供冻结的语言模型智能体使用，但现有优化器无法联合解决工作流中故障发生位置、导致故障的机制以及如何将第三方技能的相关知识局部复用的问题。我们提出工作流局部机制学习（WML）。其节点-机制归因方法识别故障工作流节点、涉及的机制以及最小有效编辑目标，将单一机制缺陷路由至L3资源，将跨机制关系缺陷路由至L2组合协议。随后，一个六模块的工作流引导技能优化（WGSO）循环选择考虑来源与作用范围的第三方知识，应用受限补丁，评估候选方案，并将验证结果存储至优化器端内存。在SpreadsheetBench上，WML在DeepSeek和Qwen3.6-Flash上分别达到90.33±1.53和74.67±3.51的硬准确率；无需额外优化，学得的技能迁移至WikiTableQuestions，分别取得84.00±2.00和83.00±2.00的指称准确率。在Compiler-Supported50上，WML同时取得了最高的硬通过率和最低的每个成功任务成本；与直接使用SkillAgent相比，编译执行大幅减少了令牌和调用次数，同时保留了大部分成功任务。代码和制品见https://github.com/xiaolin9595/workflow-localized-mechanism-learning。

## Abstract
Agent Skills package reusable procedural knowledge as external artifacts for frozen language-model agents, yet existing optimizers do not jointly resolve where a failure occurs in a workflow, which mechanism caused it, and how relevant knowledge from third-party Skills should be reused locally. We introduce Workflow-Localized Mechanism Learning (WML). Its Node--Mechanism Attribution identifies the failed workflow node, implicated mechanisms, and smallest valid edit target, routing single-mechanism defects to L3 resources and relational defects across mechanisms to L2 composition protocols. A six-module Workflow-Guided Skill Optimization (WGSO) loop then selects provenance- and scope-aware third-party knowledge, applies bounded patches, evaluates candidates, and stores verified outcomes in optimizer-side memory. On SpreadsheetBench, WML reaches 90.33 +/- 1.53 and 74.67 +/- 3.51 Hard Accuracy with DeepSeek and Qwen3.6-Flash, respectively; without additional optimization, the learned Skills transfer to WikiTableQuestions with 84.00 +/- 2.00 and 83.00 +/- 2.00 Denotation Accuracy. On Compiler-Supported50, WML attains both the highest hard-PASS rate and the lowest cost per successful task; compiled execution sharply reduces tokens and calls relative to a direct SkillAgent while retaining most of its successful tasks. Code and artifacts are available at https://github.com/xiaolin9595/workflow-localized-mechanism-learning.

## 1. 核心问题与整体含义（研究动机和背景）
- 语言模型智能体（如调用工具、执行代码的智能体）的性能不仅依赖模型权重，还依赖于可复用的程序性知识（即 Agent Skills）。现有的 Agent Skills 优化器（如 SkillOpt、SkillGrad）虽然能够通过轨迹反馈对技能文档进行编辑，但它们无法同时解决三个问题：**工作流中故障发生在哪个节点？是哪个机制导致了故障？以及如何在局部复用来自第三方技能的已有知识？**
- 当前方法存在“目标歧义”：在同一工作流节点内（如状态提交），故障可能源于单个机制的规则缺失（应编辑 L3 资源），也可能源于多个机制间的协调关系不完整（应编辑 L2 组合协议）。不考虑这种区分会导致全局重写、重复已有资源或把任务特定规则错误地放入工作流主体。
- 本文提出 **工作流局部机制学习（WML）** ，通过节点-机制归因将故障定位到节点、机制及缺陷关系，并路由到正确的编辑目标（L3 或 L2），再结合第三方知识复用形成闭环。

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：将结构化技能优化分解为**工作流局部诊断**和**知识复用**。通过节点-机制归因（Node–Mechanism Attribution）确定故障节点、可复用机制集合、缺陷类型（单一指导缺陷 / 多关系缺陷）以及类型化的编辑目标地址（L3 资源或 L2 组合协议）。然后通过六模块的 **工作流引导技能优化（WGSO）** 循环执行：执行评估 → 归因 → 上下文获取 → 受限补丁 → 验证门控 → 记忆更新。
- **关键技术细节**：
  - **节点-机制归因状态**：定义归因状态 `A = (n, Γ, ρ, τ)`，其中 n 为故障工作流节点（如上下文获取、目标绑定、操作选择、执行/变换、状态提交、验证/终止），Γ 为诊断出的可复用机制集合，ρ 为缺陷关系（single-guidance / multi-relation），τ 为类型化编辑地址（包含层、文件、节）。路由合约：single-guidance → L3 资源；multi-relation → L2 组合协议。
  - **归因实现**：诊断器根据任务结果、轨迹、评估反馈、当前 L2/L3 内容及需保留的成功证据，提出机制锚点；确定性注册表将锚点映射到合法节点和地址候选；守卫解析器通过检查指导覆盖度确定缺陷类型，并分配最小可编辑节。若存在冲突或证据不足则弃权。
  - **WGSO 循环**（Algorithm 1）：每一轮从训练批次执行评估开始，经归因聚合为本地修复提议；检查现有指导是否足够；若不足则从第三方知识索引检索相关记录（X_t）；按归因类型分别调用 Patch_L3 或 Patch_L2-comp 生成候选技能；计算结构化差异；通过 ValidateAndGate 验证结构合法性并在同一批次上重新评估，只有经门控接受的候选才更新部署技能，同时更新优化器端内存（诊断记录、结果记录、补丁策略记忆 PSM）。
  - **第三方知识复用**：只在部署技能和优化器内存指导不足时才检索，且外部记录不会逐字写入部署制品，而是经适配、合并或拒绝后再经门控决定是否写入。
  - **Patch-Strategy Memory（PSM）**：按归一化归因签名索引，存储成功的编辑类型、范围、保留约束、后置条件及评估结果。只记录验证过的改进，拒绝或回退的记录仅保留为负面结果但不更新 PSM。这帮助避免重复错误编辑。
- **公式与算法（文字说明）**：结构化技能 `S_t = (S^{L1}_t, S^{L2}_t, S^{L3}_t)`；执行评估产生 `E_t`；归因产生 `A_{t,i}`；若指导不足则检索 `X_t`；补丁生成候选 `\hat{S}_{t+1}`；验证门控输出 `(g_t, S_{t+1})`。WGSO 整体为 `(S_{t+1}, M_{t+1}, K_{t+1}) = WGSO(S_t, M_t, K_t, B_t; F)`。即给定当前技能、优化器内存、知识索引、训练批次和冻结执行器，输出下一轮技能、内存和索引。

## 7. 优点
- **方法创新**：首次将工作流节点、机制归因与类型化编辑地址结合起来，解决了现有技能优化中的目标歧义问题。通过 single-guidance vs multi-relation 区分 L3/L2 编辑，实现最小有效编辑。
- **闭环设计**：WGSO 实现了诊断、检索、补丁、验证、记忆更新的完整闭环，且第三方知识经过归因条件约束才纳入，避免盲目引入。
- **知识复用机制**：对第三方技能的利用是程序员级的局部修复而非简单拼接；PSM 从历史成功编辑中学习策略，进一步优化过程。
- **实验结果扎实**：在两个骨干、两个基准（含迁移）、编译效率等多个维度上均有显著领先，且消融实验验证了各组件的必要性。Compiler 实验通过统一编译器和运行时环境，排除了方法特定适配的不公平因素。
- **可审计性**：归因状态包含支持轨迹和保留约束，编辑差异可机械检查，有利于可信部署。
- **实用性**：优化开销仅为离线一次完成，成品技能可被下游复用；编译执行模式提供了效率与准确率的良好折中，支持“一次学习、多次编译”的范式。

## 8. 不足与局限
- **领域局限**：实验完全基于电子表格智能体，节点本体、机制词汇、L2/L3 架构需要在软件维护、浏览器控制、具身任务等其他领域验证。
- **迁移测试范围有限**：WikiTableQuestions 被转换为电子表格形式执行，因此迁移证据仅支持在该执行设置内的跨基准迁移，并非通用领域 OOD 迁移。
- **消融实验粒度**：仅对三个主要组件（归因、知识增强、元策略）进行消融，未进一步拆解归因内部（如诊断器、注册表、守卫解析器）或检索模块的贡献。
- **统计检验**：报告均值±标准差，未使用显著性检验或置信区间；种子数 3 较小，但考虑到重复性一致（标准差较小），结论仍可靠。
- **评估门控**：目前使用同批次比较（同一训练批次），未进行独立长程回归评估；未来应构建独立回归集。
- **基线处理公平性**：基线使用原生算法（训练、选择、轨迹重用）并与 WML 共享相同优化数据规模和评估设置，但未控制优化迭代次数或检索机制（SkillOpt 等无检索），因此对比是整体优化器的比较而非孤立组件对比。
- **伦理考虑**：智能体执行代码或修改工作簿可能破坏文件、泄露数据或执行未授权操作。论文提出了沙盒执行、权限最小化、日志审计等建议，但在实际部署中需更严格的防护。
