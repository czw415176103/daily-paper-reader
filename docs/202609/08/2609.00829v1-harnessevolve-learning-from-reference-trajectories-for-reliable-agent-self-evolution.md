## 摘要
自我进化的智能体通过优化其“控制框架”——提示、技能、工具和执行逻辑——基于环境反馈来推进自主性。然而，这一范式受到三个挑战的阻碍：\textit{信用分配失败}，即终端成功/失败反馈使得难以判断哪一步导致了错误；\textit{捷径学习}，即智能体记忆任务特定模式而非获得可泛化的能力；以及\textit{灾难性遗忘}，即不受保护的更新降低了先前获得的能力。在本文中，我们介绍了HarnessEvolve，一个从参考轨迹中学习以实现可靠智能体自我进化的自我进化框架。HarnessEvolve将执行智能体与进化流程解耦，将执行、评估、优化和门控分配给独立的智能体模块，从而实现可泛化且稳定的控制框架改进。具体而言，HarnessEvolve通过生成参考轨迹（在给定地面真值答案时产生的执行路径）并将失败执行与之对齐以提取错误信号，从而克服信用分配失败，这些错误信号被聚类以揭示系统性失败模式。为防止捷径学习和灾难性遗忘，候选控制框架更新必须通过两个门控：一个质量门控，过滤数据泄漏和提示膨胀；一个性能门控，在每次更新在当前批次上有所改进且不降低近期批次性能时接受该更新，并在保留集上执行周期末验证以选择性能最佳的已接受智能体快照。我们在涵盖开放领域和企业场景的多个基准上进行了广泛实验，使用了不同的模型和智能体框架。结果表明，HarnessEvolve在所有基准和设置中持续优于最先进的基线，证实了其跨任务领域的可靠性。

## Abstract
Self-evolving agents advance toward autonomy by optimizing their harness---prompts, skills, tools, and execution logic---based on environmental feedback. This paradigm, however, is hampered by three challenges: \textit{credit assignment failure}, where terminal success/failure feedback makes it ambiguous which step caused the error; \textit{shortcut learning}, where agents memorize task-specific patterns rather than acquire generalizable capabilities; and \textit{catastrophic forgetting}, where unguarded updates degrade previously acquired competence. In this paper, we introduce HarnessEvolve, a self-evolving framework that learns from reference trajectories to achieve reliable agent self-evolution. HarnessEvolve decouples the execution agent from the evolutionary pipeline, assigning execution, evaluation, optimization, and gating to independent agent modules, enabling generalizable and stable harness improvements. Specifically, HarnessEvolve overcomes credit assignment failure by generating reference trajectories (execution paths produced when given the ground-truth answers) and aligning failed executions against them to extract error signals, which are clustered to reveal systematic failure patterns. To prevent shortcut learning and catastrophic forgetting, candidate harness updates must pass two gates: a quality gate that filters data leakage and prompt bloat, and a performance gate that accepts each update if it improves on the current batch without degrading recent batches, with epoch-end validation on a held-out set selecting the best-performing accepted agent snapshot. We conduct extensive experiments on several benchmarks spanning open-domain and enterprise scenarios, using different models and agent frameworks. Results demonstrate that HarnessEvolve consistently outperforms state-of-the-art baselines across all benchmarks and settings, confirming reliability across task domains.

### 1. 论文的核心问题与整体含义（研究动机和背景）

自进化智能体（Self-evolving Agents）试图通过基于环境反馈优化自身的“控制框架”（Harness，包括提示词、技能、工具和执行逻辑），从而逐步摆脱对人工设计的依赖，实现更高的自主性。然而，这一范式在实际应用中面临三大系统性挑战：

- **信用分配失败（Credit Assignment Failure）**：在长周期任务中，智能体往往仅能获得最终二元成功/失败信号，无法定位是哪个中间步骤导致了最终错误；后续错误通常是起始错误的级联下游后果，若直接对整条轨迹进行反思，易导致错误归因混乱，使优化方向失效。
- **捷径学习（Shortcut Learning）**：无保护机制时，智能体倾向在控制框架中直接硬编码任务答案、注入过多任务特化的上下文示例，以数据泄漏或提示膨胀的方式虚增训练集正确率，而未获得真正可泛化的能力。
- **灾难性遗忘（Catastrophic Forgetting）**：每一次控制框架更新仅针对当前一小批轨迹数据优化，可能与先前已获得的能力相互冲突，导致在多次迭代中逐步丢失老知识。

作者指出，仅依靠迭代式的提示优化算法无法根治上述问题，必须在系统架构上进行解耦设计。为此，论文提出 **HarnessEvolve**：一种借助参考轨迹、以可靠方式进行智能体控制框架自进化的框架，核心逻辑是分离“执行”与“进化”两个流程，并让执行、评估、优化、门控分别由独立模块承担，以确保进化过程的可审计性和不可被“刷分”性。

### 2. 论文提出的方法论

**2.1 总体架构：解耦多智能体**
HarnessEvolve 将整个自进化流水线拆分成四个独立智能体模块：

- **A_exec（执行）**：使用当前控制框架运行 T_train 中的任务；同时也被用来在给定“问题 + 真实答案”的情况下生成参考轨迹。
- **A_eval（评估）**：在优化中评估执行准确率，判断并标记失败轨迹；在参考轨迹生成中负责验证该参考轨迹是否真实，排除“直接将已知答案输出”的伪造捷径。
- **A_opt（优化）**：分析失败轨迹、与参考轨迹对齐比较、聚类错误并生成候选控制框架修改。
- **A_gate（门控）**：对候选更新做两轮审查，分别对应质量门与性能门。

**2.2 参考轨迹生成与误差诊断**
在主优化循环开始前，HarnessEvolve 为 T_train 中每个问题附加真实答案，让 A_exec 最多尝试 T_att 次生成参考轨迹 τ⁺。A_eval 负责滤除非真实路径，只有验证通过的轨迹才存入全局缓存 C。当某次失败发生，A_opt即可将该失败轨迹与对应参考轨迹逐点对比，找出“第一分歧点 t\*”——即二者最早出现行动差异的位置——并将其认定为根因所在，而非将整条轨迹均视为错误。通过这种方式定位错误信号 F_i = (s_i, m_i, h_i)（严重度、错误原因、修复提示）。若某任务没有参考轨迹，则退化为仅对失败轨迹进行单轨迹分析。

**2.3 错误聚类**
优化时各批次产生的实例级错误信号 F_i 被依据错误原因 m_i 聚成组 P = {C_k}，聚类遵循三个原则：

- **基于原因分组**：同类根因汇聚成一簇，保证修复策略的连贯一致；
- **根因优先**：优先按“第一分歧点”判定根因，避免将级联症状当作根因来处理；
- **长尾保护**：保留单成员聚类，防止低频但关键的错误模式被大簇吞噬。

**2.4 候选更新生成**
A_opt 根据聚类结果（含簇内代表性错误轨迹及修复方向）对控制框架中的具体文件（提示词、技能、工具描述或执行逻辑代码等）提出一系列定向修改，形成候选更新集合 Δ_harness。

**2.5 双层门控机制**
- **质量门（Quality Gate）**：由独立的 A_gate 进行（1）数据泄漏检查（判断是否在更新中内嵌训练问题-答案对，以 LLM-as-judge 评分超过 η_leak 则拒绝）；（2）提示膨胀检查（统计新注入的上下文示例数量，超过 η_blo 则拒绝）。被拒项会附带拒绝理由 ρ 退回重修，超过 Trev 次仍不满足则放弃。
- **性能门（Performance Gate）**：候选更新构造的候选智能体需在当前批次 B_j 上比旧版本准确率提升至少 δ，同时在其最近 R 个批次上的准确率下降不超过 ϵ。只有当 $\text{Acc}(A_{candidate}, B_j) - \text{Acc}(A_{current}, B_j) \ge \delta$ 且 $\max_{l \in [\max(1,j-R),j-1]}[\text{Acc}(A_{current},B_l) - \text{Acc}(A_{candidate}, B_l)] \le \epsilon$ 时，才被接受为快照存入池 V，并升级为当前活跃智能体。

**2.6 周期末验证**
每个 epoch 结束后，在验证集 T_val 上从快照池 V 中选择最优快照作为本周期最终智能体 A\*，实现训练中“不进则退”的保障。循环在达到 epoch 上限 E 或验证集准确率连续 Pep 个周期无提升时终止。

### 6. 论文的主要结论与发现

- HarnessEvolve 在三个开源基准（SearchQA、OfficeQA、SpreadsheetBench）和两个企业内测基准（CloudCoreNetwork-QA、Wireless-QA）的**所有**模型和框架配置下均取得最佳准确率。例如 CloudCoreNetwork-QA 上 Qwen3.6-27B 从 Base 的 43.4% 提升到 86.9%，超越最强基线 GEPA 21.6 个百分点；Wireless-QA 上 DeepSeek-V4-Flash 从 85.9% 提升到 92.8%，超过 ACE 约 2.7 个百分点。
- 经过 HarnessEvolve 优化的技能可直接迁移至其他智能体框架且性能不降反升，表明其学到的能力具有跨框架的通用性。
- 双层门控机制能有效筛选大量低质量候选更新；在消融中有效证明了参考轨迹比较和错误聚类对准确率的贡献。

### 7. 优点

1. **问题定位精准而有针对性的系统级方案**：同样面对“稀疏奖励”问题，HarnessEvolve 提出借助“第一分歧点”进行根因分析，有效绕过信用分配模糊难以根本诊断的问题。
2. **结构新颖且安全性设置完备**：将执行与进化完全解耦，配合独立门控模块，防止优化过程被执行智能体自身操控；质量门（防泄漏和提示膨胀）+ 性能门（防遗忘）使自我进化具备了理论上的收敛保障。
3. **泛化性得到实际验证**：在不同任务类型（开放问答、企业文档、数据表格、文本转 SQL）、不同模型（通用模型与领域微调模型）和多种智能体框架上做了较广泛验证，增强结果可信度。
4. **系统仍保留真实的资源控制性**：在参考轨迹生成后将这些成功路径存储缓存，后续无需重复生成，整体计算开销得到一定控制。
5. **具有直接应用价值**：适用于企业内部以私有数据为背景的“无人工监督自动迭代优化”场景，对数据隐私敏感的部署有实际意义。
