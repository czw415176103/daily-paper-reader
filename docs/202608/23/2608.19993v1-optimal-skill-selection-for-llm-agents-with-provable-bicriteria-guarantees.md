## 摘要
将可复用的技能文档加载到有界上下文窗口，现在是大型语言模型（LLM）智能体获取任务特定能力的主要方式，这使得技能选择成为任务性能和令牌成本的一阶决定因素。然而，当前的智能体通过语义相关性独立地对技能进行评分，并通过top-k或贪心打包的方式组装技能集，对所选技能集没有质量保证或成本意识。因此，冗余或选择不当的技能会浪费稀缺的上下文令牌，甚至可能降低性能。我们首次对所选技能集如何塑造执行结果进行了建模，并将技能选择转化为一个优化问题：在硬令牌预算下选择一个技能集，以最大化单调子模收益减去上下文惩罚。针对这个问题，我们开发了最佳前缀选择（BPS）算法，这是一种多项式时间算法，并证明了我们所知的第一个技能选择性能保证：一个双准则$(1-1/e,1)$近似，其收益系数在多项式时间内是最优的。在一个污染控制的BigCodeBench变体上，BPS优于所有基线，在比最强发布路由器少$28\%$的令牌上，达到了$0.73$的实测任务成功率，而发布的技能路由器、文本检索器和执行器自身选择的成功率则为$0.20$--$0.52$。

## Abstract
Loading reusable skill documents into a bounded context window is now the primary way large language model (LLM) agents acquire task-specific capabilities, which makes skill selection a first-order determinant of task performance and token cost. Yet current agents score skills independently by semantic relevance and assemble the set by top-$k$ or greedy packing, with no quality guarantee or cost awareness on the selected set. As a result, redundant or poorly chosen skills waste scarce context tokens and can even degrade performance. We give the first model of how the selected skill set shapes execution outcomes and cast skill selection as an optimization problem: choose a skill set under a hard token budget to maximize a monotone submodular benefit minus context penalty. For this problem, we develop Best Prefix Selection (BPS), a polynomial-time algorithm, and prove, to our knowledge, the first performance guarantee for skill selection: a bicriteria $(1-1/e,1)$ approximation whose benefit coefficient is optimal in polynomial time. On a contamination-controlled BigCodeBench variant, BPS outperforms all the baselines, reaching $0.73$ measured task success versus $0.20$--$0.52$ for released skill routers, text retrievers, and the executor's own selection, on $28\%$ fewer tokens than the strongest released router.

## 论文总结：面向LLM智能体的最优技能选择

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM智能体（如 Codex、Claude Code）越来越依赖加载“可复用技能文档”来获得任务特定能力。技能选择与执行是两阶段机制：先根据查询选择技能，再把选中技能文档加载进上下文窗口执行任务。
- **核心问题**：随着技能库增长到数百上千条目，元数据本身就可能超出上下文预算；且现有方法大多“独立按语义相关性对技能打分，再用 top-k 或贪心打包”，缺乏集合级质量保证和 token 成本意识，导致：
  - 冗余技能浪费稀缺上下文 token；
  - 选择不当可使通过率下降最多 21%；
  - 在部分任务上，选中错误技能甚至可能使表现低于“不使用任何技能”的基线。
- **关键洞察（来自真实实验）**：技能选择是“预算约束下的集合级决策”而非“单技能排序”。例：只覆盖一种能力的技能集成功率为 0；互补技能达到 93%；在此基础上添加冗余技能仅提升 1pp，而添加语义相关但任务无关的技能会降低 23pp。
- **论文定位**：作者宣称这是**第一个**对“所选技能集如何影响执行结果”的结构化建模，以及**第一个**具有可证明性能保证的技能选择算法。

### 2. 方法论

#### 2.1 结构化目标模型

- **潜在能力空间**：假设存在 $d$ 维能力空间。每个技能 $s_i$ 有潜在能力供给向量 $\mathbf{u}_i \in \mathbb{R}^d_+$；每个查询 $q$ 有潜在能力需求向量 $\mathbf{w}_q \in \mathbb{R}^d_+$。
- **能力收益（Gross Benefit）**：
$$G_E(q, S) := \sum_{k=1}^d \eta^E_k \cdot w^q_k \cdot h_k\left(\lambda^E_k \sum_{i\in S} u_{i,k}\right)$$
其中 $h_k$ 为不减凹函数（取 $h_k(x)=1-e^{-x}$），刻画同一能力维度内的收益递减（冗余）与跨维度互补性。$G_E$ 是单调子模函数。
- **退化惩罚（Degradation Penalty）**：$c_E(S) := \kappa_E \cdot \ell(S)$，对注入的 token 长度线性收费。
- **优化问题**：在硬 token 预算 $B$ 下最大化 $\max_{S \in \mathcal{F}_B} F_E(q,S)$，其中 $\mathcal{F}_B = \{S \subseteq [L]: \ell(S) \le B\}$，$F_E = G_E - c_E$。
- **计算困难性**：令 $\kappa_E=0$ 可归结为预算最大覆盖问题（NP-hard）；惩罚项使目标可负，排除常数乘法近似，需引入双准则保证。

#### 2.2 BPS 算法（Best Prefix Selection）

- 算法为“种子规模为 2 的部分枚举密度贪心”：
  1. 枚举所有规模 ≤2 的可行种子；
  2. 从每个种子出发，反复添加“边际收益/ token 最大”的可行技能，形成贪心链；
  3. 记录链上**每个前缀**（而不只是终点）；
  4. 返回在所有记录前缀中使 $\hat{F}$ 最大的集合。
- 时间复杂度 $O(dL^4)$（$d$ 为能力维数，$L$ 为技能库大小，实践中 $L$ 为高召回检索后的短列表规模）。

#### 2.3 理论保证

- **Theorem 1（核心结果）**：BPS 输出满足
$$\hat{F}(S_{\text{BPS}}) \ge (1-1/e)\hat{G}(T) - \hat{\kappa}\ell(T), \quad \forall T \in \mathcal{F}_B$$
即双准则 $(1-1/e, 1)$ 近似：收益系数 $1-1/e$ 在多项式时间内最优（Feige, 1998 下不可改进），惩罚系数为 1。
- **证明创新**：通过“预算对齐插值”将密度链上某个分数点的界，转换为相邻两个实际记录前缀的凸组合，由于惩罚与约束共享同一长度坐标，两个插值恰好对齐，从而以零加法损失得到紧系数。
- **误差传递（Proposition 1）**：拟合目标与真实执行效果的均匀误差 $\varepsilon$，加上优化误差 $\delta$，端到端选择遗憾 ≤ $2\varepsilon + \delta$。

#### 2.4 参数学习

- 有效需求/供给直接通过两个文本编码器估计（非负输出层保证子模性），上下文敏感度 $\hat{\kappa}^E$ 与编码器联合校准。
- 仅需 281 个参数（任务集、技能库固定时退化为查找表），从 pass/fail 执行记录即可拟合。

### 3. 实验设计

- **基准测试（核心贡献之一）**：构建“污染控制”的 BigCodeBench 变体：
  - 将标准库替换为 16 个私有模块，横跨 $d=5$ 个能力族；
  - 任务准入条件严格：仅当“私有模块方案通过测试，同时标准库方案及所有单能力混合方案失败”时任务才被纳入——不到 1/3 的 fork 任务通过；
  - 编写 47 个技能文档，其中 31 个构成技能库：包括单模块技能（从短片段到完整教程）、双模块手册、以及仅覆盖相似但任务不需要的函数的干扰项。
- **全部实验基于 63,596 次对冻结 Qwen3-32B 执行器的真实执行**。

- **实验一：目标函数有效性（预测与参数恢复）**
  - 对比基线：Additive fit、Shapley 评分、Datamodels、DeepSets、Set Transformer、Linear response（自身消融）。
  - 两种协议：外推（训练集规模 ≤2 的技能组合，预测 ≥3 的组合）和未见文档（单独见技能，预测配对）。
  - 指标：持有集上的配对排序准确率、成功率的预测误差；参数恢复用 AUC。
  - 结果：结构化目标在两种协议下预测最准、预测误差在 1pp 内；参数恢复 AUC 0.996。
  - 选择质量：结构化目标达到经验上限的 95%，其他可解释模型至少低 0.37。

- **实验二：优化质量（隔离优化误差 δ）**
  - 固定同一拟合目标，80 个选择实例（覆盖持有任务、不同 token 预算水平、不同惩罚系数）。
  - 对比基线：Top-k、MMR、DPP-MAP（单技能打分 + 启发式组装）、Density greedy、Best-of-100（集合级打分 + 启发式搜索）。
  - 结果：BPS 在全部 80 个实例上达到精确最优（穷举验证）；密度贪心 44%、最佳 100 45%；单技能评分法仅 7.5%。

- **实验三：端到端选择质量**
  - 对比真实部署系统：BM25、Dense retriever、SkillRouter（发布版，top-1 与满预算重排两种）、Graph-of-Skills（作者发布实现）、Executor self-select（执行器自己选）。
  - BPS 两种实例化：查找表编码器与神经编码器（text-embedding-v4 嵌入投影到 64 维，先注释预热再在线训练）。
  - 结果：BPS（查找表）0.73 成功率、680 令牌；神经编码器 0.68、716 令牌；最强路由器 0.43、940 令牌；执行器自选 0.51、~600 令牌。

### 6. 主要结论与发现

- 技能选择应被视为“带 token 预算的集合级优化”，目标为单调子模收益减线性上下文惩罚，能显式建模冗余、互补与上下文成本。
- BPS 算法实现了紧的 $(1-1/e, 1)$ 双准则保证，收益系数在多项式时间内最优；提出的“预算对齐插值”证明技术是取得该紧系数的关键。
- 结构化目标从 pass/fail 记录拟合后（281 参数）即可精确预测执行结果并恢复隐藏能力覆盖矩阵（AUC 0.996），比参数多 60 倍的神经网络集回归器更准。
- 在真实部署对比中，BPS 以 0.73 成功率、680 令牌，全面优于所有发布路由器/检索器/执行器自选（0.20–0.52），并节省 28% 的 token。

### 7. 优点

### 8. 不足与局限

- **算力细节缺失**：未报告 GPU、训练时长等资源信息，不利于复现成本评估。
