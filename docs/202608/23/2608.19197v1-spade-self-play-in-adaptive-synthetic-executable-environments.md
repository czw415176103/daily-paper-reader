## 摘要
持续的自我改进需要不断扩展的、自生成的、多样化的自适应目标池。对于语言智能体而言，现有的训练环境池（手工策划、静态合成或冻结验证器）在学习者规模扩展时保持了目标分布的固定。我们提出了SPADE（自适应合成可执行环境中的自对弈），一种自对弈强化学习框架，其中单个大语言模型扮演两个角色：一个环境设计者，编写完整的长视野训练环境作为可执行代码，具有OpenAI Gym风格的reset()/step()接口；以及一个推理智能体，学习在这些环境中行动。每个环境都是有状态的、多轮次的（状态转换、奖励函数和验证代码），因此一个接口可以涵盖推理问题和多步智能体工具使用。推理智能体的遗憾值通过其在有特权提示和无特权提示下奖励之间的差距来估计；在优化这一遗憾信号时，环境设计者学习将环境定位在智能体能力的边缘，同时保持环境的可行性。通过大量实验，我们发现几个对成功至关重要的组成部分：将环境设计者基于从大型预训练语料库中采样的文档进行接地，并为其提供累积的环境记忆。扩展到300亿参数模型，SPADE在八个预留的数学、科学、代码和推理基准上平均比最强的固定环境基线提升+5.3，在BFCL-v4多轮工具使用上提升+5.7，在ACEBench-Agent上提升+13.9；在游戏设置中，相对于最强基线的优势随模型规模增大而增大。通过使环境设计本身成为可学习的组件，SPADE向开放式自我改进迈出了具体的一步。

## Abstract
Continuous self-improvement requires an ever-expanding pool of self-generated, diverse, adaptive goals. For language agents, existing training environment pools (hand-curated, statically synthesized, or frozen-verifier) keep the goal distribution fixed as the learner scales. We introduce SPADE (Self-Play in Adaptive Synthetic Executable Environments), a self-play RL framework in which a single LLM plays two roles: an Environment Designer that writes complete, long-horizon training environments as executable code with an OpenAI Gym-style reset()/step() interface, and a Reasoning Agent that learns to act in them. Each is a stateful, multi-turn environment (state transitions, reward functions, and verification code), so one interface spans reasoning problems and multi-step agentic tool use. The Reasoning Agent's regret is estimated using the gap between its reward with and without privileged hints; in optimizing this regret signal the Environment Designer learns to target environments at the edge of the agent's capabilities while keeping them feasible. Through extensive experimentation, we find several components critical to success: grounding the Environment Designer on documents sampled from a large pretraining corpus, and giving it an accumulated environment memory. Scaling to 30B-parameter models, SPADE improves over the strongest fixed-environment baseline by +5.3 on average across eight held-out math, science, code, and reasoning benchmarks, and lifts the tool-use setting by +5.7 on BFCL-v4 multi-turn and +13.9 on ACEBench-Agent; on the games setting, the margin over the strongest baseline grows with model scale. By making environment design itself a learnable component, SPADE takes a concrete step toward open-ended self-improvement.

### 1. 论文核心问题与整体含义（动机与背景）

- **核心瓶颈**：语言智能体的持续自我改进依赖于一个不断扩展、多样化且自适应的训练环境池。然而，现有训练环境来源（人工策划、静态合成、冻结评估器）都存在缺陷：
  - **人工策划**：扩展速度受限于人力；
  - **静态合成**：生成器固定，环境空间不会随智能体能力增长而扩展，智能体很快“榨干”环境；
  - **冻结评估器/生成器**：无法随学习者的进步而适应。
- **根本问题**：环境分布固定，智能体在消耗完既定环境后便停止提升，缺乏**开放性**和**协同进化**能力。
- **论文主张**：将“环境设计”本身变为一个**可学习的、通过RL训练的组件**，使环境生成与智能体能力形成共同进化（co-evolution），实现开放式持续自我改进。

### 2. 论文方法论

**核心思想：单一LLM承担双重角色——环境设计者（Environment Designer）与推理智能体（Reasoning Agent）**

- **双角色自对弈**：同一个大语言模型 πθ 通过不同的系统提示词（角色 =D 或 =A），交替扮演：
  - **环境设计者（ED）**：生成完整的可执行Python代码（Gym风格，带 reset()/step() 接口），表示一个完整的MDP（状态空间、转移函数、奖励函数、验证代码），并附带一个“特权提示”（hint）；
  - **推理智能体（RA）**：在生成的环境中行动，通过多轮交互完成目标任务以获取奖励。
- **代码即环境（Code-as-Environment）**：将环境表示为可执行Python程序，使一个统一接口同时覆盖：
  - 单轮推理任务（一步到达终态）
  - 多轮智能体工具使用任务（连续交互和状态转移）
  - 理论上任意可计算MDP均可被表达，环境空间是**无界的**。
- **提示遗憾奖励（Hint-based Regret Reward）**（核心公式）：

  $$r_D(e) = \bar{r}_A(e|h) - \bar{r}_A(e)$$

  - 即“带提示的平均回报”减去“不带提示的平均回报”；
  - **高遗憾** → 环境落在智能体学习前沿（有提示可解、无提示难解）；
  - **低遗憾且两者都高** → 环境已被掌握；
  - **低遗憾且两者都低** → 环境不可解。
  - 这实现了PAIRED的minimax regret目标，无需单独的对抗者。
- **训练算法**：GRPO（Group Relative Policy Optimization），带每个角色的独立优势标准化、非对称裁剪（εlow=0.2, εhigh=0.28）、截断重要性采样（由于ED更新延迟）。
- **语料库接地（Corpus Grounding）**：每轮ED生成环境时，从预训练语料（如DCLM、MegaScience、Nemotron代码语料库）中采样新文档，以提供外部新颖性和多样性。
- **环境记忆（Environment Memory）**：记录历史环境及其遗憾分数，避免重复已掌握的任务，聚焦高遗憾种子并规避太容易/太难的环境。
- **稳定训练细节**：ED更新延迟k个rollouts、EM（Environment Memory）带200条记录的容量上限、提示词由ED自己生成、环境验证（语法检查、可执行性冒烟测试）。

  - 仅覆盖Qwen3（3个）和Nemotron（1个，部分评测）模型家族，未在更大规模（如>100B）或更多架构上验证；
  - 算力资源和训练时间未报告，不利于复现成本估算；
  - 对比系统（AgentScaler、AWM等）协议不完全一致，公平性受限；
  - 40次rollout × 24环境总数相对有限（约960个环境）；长期有效性（如扩展到数千步）未验证。
- **风险与偏差**：
  - 提示遗憾在有噪声时会为小骨干模型带来负值（4B/8B观察到长段负值，意味着提示有时会误导）；
  - ED生成环境时的“验证”计算资源成本较高（工具使用场景还增加了解析和可解性检查）；
  - 存在奖励黑客风险，虽然论文有验证过滤机制但未深度讨论防攻击场景；
  - 环境生成过程高度依赖基座模型质量，基座能力不足时环境质量可能显著下降；
  - 语言环境多样性测量（Vendi Score）仅基于SBERT嵌入，可能低估语义层面更细粒度的多样性差异。
