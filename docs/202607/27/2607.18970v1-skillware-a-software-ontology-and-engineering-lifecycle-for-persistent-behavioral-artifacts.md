## 摘要
Agent技能已成为跨独立AI Agent系统的持久行为工件。它们将自然语言任务规范与元数据及可选的引用、脚本、资产、钩子、包清单、测试和配套接口相结合。现有研究解释了技能如何被规范、执行、维护和演化，但缺乏定义这些工件为独立软件对象的本体。本文引入Skillware作为软件抽象，将软件工程扩展至Agent系统中的持久行为工件。技能工件规定了可复用的任务行为；Skillware单元通过独立标识和生命周期将该工件作为软件进行管理。兼容的Agent宿主激活该单元以进行运行时解释。三个必要条件界定了类别成员资格：行为优先性、独立软件身份以及Agent宿主执行关系。生命周期连续性记录同一单元标识是否在更新、维护、回滚和移除过程中持续存在，作为一个独立的软件级属性。证据结合了Agent技能规范、与20,556个仓库标识符相关的138,138个去重SKILL.md记录的冻结语料库、独立实证研究、15个类别边界案例以及13个固定修订的工程实现。证据确立了一个重复出现的工件包络、可分离的软件身份、兼容的执行路径以及生命周期工程压力。Skillware提供了软件本体和工程生命周期，使Agent能力能够成为可识别、可组合、可维护和可演化的软件工件。

## Abstract
Agent Skills have become persistent behavioral artifacts across independent AI agent systems. They combine natural-language task specifications with metadata and optional references, scripts, assets, hooks, package manifests, tests, and companion interfaces. Existing studies explain how Skills are specified, executed, maintained, and evolved, but lack an ontology that defines these artifacts as independent software objects. This paper introduces Skillware as the software abstraction that extends software engineering to persistent Behavioral Artifacts in agent systems. A Skill Artifact specifies reusable task behavior; a Skillware Unit manages that artifact as software through an independent identity and lifecycle. A compatible Agent Host activates the unit for runtime interpretation. Three necessary conditions operationalize category membership: behavioral primacy, independent software identity, and an Agent Host execution relationship. Lifecycle Continuity records whether the same unit identity persists through update, maintenance, rollback, and removal as a separate software-grade property. Evidence combines the Agent Skills specification, a frozen corpus of 138,133 content-deduplicated SKILL.md records associated with 20,556 repository identifiers, independent empirical studies, 15 category-boundary cases, and 13 fixed-revision engineering implementations. The evidence establishes a recurring artifact envelope, separable software identities, compatible execution paths, and lifecycle engineering pressure. Skillware provides the software ontology and engineering lifecycle through which agent capabilities can become identifiable, composable, maintainable, and evolvable software artifacts.

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- **Skillware Ontology（本体）**：围绕持久行为工件定义一组互相关联的概念：
  - **Behavioral Source（行为源）**：持久化的自然语言指令、约束、策略、示例等，作为可复用任务行为的载体。
  - **Skill Artifact（技能工件）**：地址化的、以自然语言行为源为主的软件工件，规定可复用任务行为。
  - **Skillware Unit（技能单元）**：围绕一个技能工件或一组相干技能工件的**独立软件身份**，负责获取、激活、版本管理、维护和移除。
  - **Agent Host（宿主）**：用户面对的应用，负责发现/接收技能单元并激活它。
  - **Agent Runtime（运行时）**：由宿主提供或委托的执行环境，负责上下文组装、模型调用、工具路由、状态管理和Agent循环。
  - **Situated Performance / Task Outcome**：由运行时、任务、模型、上下文、工具、权限、状态共同决定的实际执行效果。

- **成员资格条件（C1–C3）与生命周期连续性（LC）**：
  - **C1 – 技能中心的行为优先性**：可复用任务行为由技能/技能套组组织，代码和资源作为辅助。
  - **C2 – 独立软件身份**：单元拥有可独立获取、安装、版本追踪的地址（如目录、包、插件）。
  - **C3 – Agent宿主执行关系**：至少有一个兼容宿主能发现、激活、加载并使用该单元。
  - **LC – 生命周期连续性**：同一单元身份在更新、维护、回滚、移除过程中持续存在，作为软件级属性（不要求所有单元都达到，而是测量属性）。

- **实现维度（Implementation Dimensions）**：描述技能单元内部结构的正交轴线，包括：
  - Atomic（最小基线）、Resource-Backed（资源支持）、Tool-Backed（工具支持）、Event-Driven（事件驱动）、Plugin-Packaged（插件打包）、Companion-Coupled（配套耦合）、Adaptation-Enabled（自适应使能）。
  - 各维度可组合，形成快照式实现画像。

- **设计模式转移**：将传统软件设计模式（如Facade、Adapter、Composite、Observer、State、Strategy）映射到Skillware单元，展示软件工程原理的介质独立性。每个模式提供参与者对应、使用条件和反例判别器。

- **Skillware工程生命周期**：一个建议的初始工作流（6步）：
  1. 定义单元与任务契约
  2. 选择实现维度
  3. 根据设计力选择设计模式
  4. 实现工程机制（确定性内核、渐进式加载、系统绑定、生命周期钩子、验证门、人控配套、自适应演化等）
  5. 评估与打包
  6. 发布、观察、维护与适应

- **身份保持演化（Identity-Preserving Evolution）**：执行证据 → 行为变更提议 → 评估 → 受控发布，单元身份得以保留。包括自演化（Self-Evolution）和协作演化（Collaborative Evolution）。
